- 去向：专项复核；处置；拟题《落水前先认识逃生工具》。

## 首批四关完整交互设计

### 汛期应急包 / flood-kit

类型：防范找物；源稿：1、9、13、32、50。

场景条件：

- 平日家中准备，无进水、无即时撤离指令
- 物品在桌面、搁架、椅子等自然位置，不设底部物品栏
- 五件物品为示例，实际需按人数、健康需要和当地指南补足

正确动画（每个处理动作0.5—1.5秒，完成帧才计数）：

1. 点击水瓶：抬起、向应急包移动、缩入包口并消失。
2. 点击食品盒：同上。
3. 点击手电筒：同上。
4. 点击收音机：同上。
5. 点击哨子：同上。

顺序：5! = 120 种正确顺序均可，不以准备时间扣花。
错误及无关输入：点击普通书、玩具或空白处仅轻反馈，不说这些物品永远没用。
收尾：包整理好仍留室内；文案提醒应急包只是事前准备，转移不要因收拾而拖延。

美术和交互验收：

- 剪影直接取对应道具原图
- 包口与道具落点对齐
- 小哨子实际画布可点击面积不小于手机约28px；可用提示辅助
- 没有数量或剂量数字

### 畅通的生命通道 / clear-corridor

类型：防范找物；源稿：28。

场景条件：

- 平日无火、无烟的楼道
- 玩家代替成年住户整理轻便的自家物品
- 有明确独立室内储物门，不与出口、楼梯间或消防设备相混

正确动画（每个处理动作0.5—1.5秒，完成帧才计数）：

1. 点击纸箱：抬起后移入自家储物门内消失。
2. 点击折叠椅：移入同一储物空间。
3. 点击空行李箱：滚入储物空间。
4. 点击玩具滑板车：推入储物空间。

顺序：4! = 24 种正确顺序均可。
错误及无关输入：点击消防设备、指示标识不移动、不发奖；不鼓励拆消防设施。
收尾：整条疏散走道畅通；防火门不被撑开；场景不突然发生火灾。

美术和交互验收：

- 四物件遮挡程度适中且处于实际通行区域
- 储物间清晰位于独立门内
- 不得把电动自行车移入住宅
- 安全出口、消防箱和通路不被HUD挡住

### 电梯停住了 / lift-wait

类型：处置交互；源稿：44。

场景条件：

- 普通垂直电梯静止困人，无坠落、火烟和伤员
- 报警通话按钮工作正常
- 人物一直留在轿厢内，侧方等待位置可见

正确动画（每个处理动作0.5—1.5秒，完成帧才计数）：

1. 点击报警通话按钮：按压回弹、指示灯变化；在一处通话气泡确认位置与人数。
2. 拖动人物至侧方远离门的位置：平稳移动、表情放松但不欢呼。

顺序：两种顺序都可；不把先移动后报警判错。
错误及无关输入：尝试撬门：门不打开，人物惊慌，提示不要扒撬轿门；楼层按钮无关反馈。
收尾：显示“已联络，安心等待”，门保持关闭；不以快速救出为胜利条件。

美术和交互验收：

- 按钮标记是场景真实面板的一部分
- 人物脚底落地，路径全在轿厢内
- 等待区不在门缝或井道内
- 没有风险倒数或虚构到达时限

### 井口边的求助 / well-call

类型：处置交互；源稿：49。

场景条件：

- 旁观者已在室外外围，无资格装备进入污水井
- 井内有人遇险，以非血腥提示说明，不要求玩家靠近查看
- 电话是离线模拟，不触发真实拨号、不收集姓名电话定位

正确动画（每个处理动作0.5—1.5秒，完成帧才计数）：

1. 点击模拟电话上的119：短拨号动效，确认地点和井内遇险情况。
2. 点击120：同样确认急救需要。
3. 拖动旁观者至更远的步道：人物退后、摆手劝阻，不跨越井口。

顺序：三项6种顺序均可；不把报警锁在摆锥桶之后。
错误及无关输入：点击井口或拖人到井口：阻止进入并回弹，提示无防护不要下井；井口不冒有色气体假装可目视识毒。
收尾：显示“求助已发出，请在外围等待”，井口仍为危险区；绝不“全场安全、伤者治愈”。

美术和交互验收：

- 电话界面与场景物体一体，不另设答案步骤栏
- 靠近井口不会发生实际进入动画
- 等待区是场景特定位置，不标通用米数安全半径
- 错误后仍能完成三项动作

## 制作与发布门禁

1. level.json只写知识和规则，皮肤JSON只写美术、摆位、状态图、关键帧；不在引擎按关卡名称分支。
2. 新关使用计时而非伪造灾害期限；既有关卡风险功能保持兼容。原有两个关卡不擅自改规则。
3. 报警、通信是本地模拟。没有后台请求、tel链接、真实定位或权限请求。
4. 逐关测试正确顺序全排列、错误无奖励、重复点击不重复计分、动画时长和状态末帧；再浏览器验收实际轮廓与触摸拖放。
