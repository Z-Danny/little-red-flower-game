# 小红花排行榜：本机版与联网扩展接口

## 当前实现

入口：关卡首页 → 小红花排行榜。排行榜独立成页，不给关卡画面增加常驻步骤条。展示昵称、地区、小红花数、名次和当前玩家；暖色背景与现有关卡绘本风格相配。

同一浏览器同一游戏地址最多 50 位本机玩家，各自保存每关历史最好成绩。新增玩家从零开始并立即成为当前玩家；已有玩家可编辑资料、点击榜单右箭头切换。首页重置仅影响当前玩家，并弹出带昵称的确认提示。

排序按总花数降序。同分同名次，使用竞赛排名：1、1、3；同分行按创建时间、ID 稳定排序，不改变并列名次。0 朵展示为“— / 未上榜”。不生成虚构排名或示例玩家。

当前两关每关最多 3 朵，共 6 朵。计分关卡来自 `levels.filter(level => level.playable)`；启用新关会自动进入计分范围，排行榜和关卡组件无需增加判断分支。关闭某关后其分数不计入当期榜单，但存档仍保留该关最好记录。若将来奖励上限不是 3，需同时调整关卡奖励、排行榜 caps 和存档校验的上限。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `app/game/leaderboard/model.ts` | 类型、输入校验、计分、并列排名、存档解析、异步 Provider 合约；不依赖 React/浏览器 |
| `app/game/leaderboard/local-provider.ts` | 本地存储适配、旧进度迁移、玩家创建/切换、读写失败处理 |
| `components/game/leaderboard/use-leaderboard.ts` | 唯一数据源装配点、异步加载/错误状态、跨标签存档变更通知 |
| `components/game/leaderboard/leaderboard-page.tsx` | 排名列表、当前玩家卡片、资料表单；不直接读取 localStorage |
| `components/game/game-app.tsx` | 关卡完成事件接入当前游玩玩家；关卡引擎完全不知排行榜存在 |
| `app/leaderboard.css` | 独立皮肤，修改榜单风格不影响计分 |
| `scripts/export-offline.mjs` | 将排行榜代码和样式一同打包为离线 HTML |

## 数据与迁移

旧 key：`little-red-flower-emergency-progress-v1`，内容为 `{ levelId: bestFlowers }`。

新 key：`little-red-flower-leaderboard-v1`：

```json
{
  "version": 1,
  "activePlayerId": "uuid",
  "players": [
    {
      "id": "uuid",
      "name": "小红花玩家",
      "region": "",
      "createdAt": 0,
      "completed": { "oil-fire": 2, "typhoon-home": 3 }
    }
  ]
}
```

首次没有新存档时迁移旧记录，不修改/删除旧 key。已有新存档时不重复迁移，因此重置或添加玩家不会重新获得旧玩家的小红花。迁移会忽略非法成绩并限制到合法上限。

新存档格式不认识或 JSON 损坏时不覆盖原内容，进入带可见警告的临时榜。浏览器禁止存储或空间不足时保留页面内存成绩并提示可能丢失。存档在 localStorage 中，没有上传任何昵称、地区、分数，也没有读取地理定位。

跨标签：监听 storage 事件；每次更新前重读存档，避免顺序操作覆盖另一标签的修改。一次游玩的奖励绑定开始时的玩家 ID，不因另一标签切换玩家而记错人。localStorage 不是事务数据库，不保证两个窗口“同时写入”的原子性；建议不要同时在两个标签游玩。此模式不具备反作弊，本机用户可自行修改存档。

文件复制只复制游戏，不能复制浏览器存档。`localhost:3002`、其他端口、GitHub Pages 与 `file://` 是不同存储环境。某些浏览器的 file 模式不持久化；必须以目标浏览器实际运行结果为准。

## 联网扩展：接口已有，服务端未实现

`LeaderboardProvider` 将以下操作统一为异步结果 `Promise<BoardSnapshot>`：

```ts
read()
createPlayer({ name, region })
updateProfile({ name, region })
switchPlayer(playerId)
recordResult(levelId, flowers, playerId)
resetCurrentProgress()
subscribe?(onChange) // 返回取消订阅函数
```

快照包含 `scope`、`current`、`entries`、`maxFlowers`、`persistence`、`notice`。目前只装配本地 Provider。联网实现应新建 `http-provider.ts` 并从 `use-leaderboard.ts` 的装配点注入；保留本地 Provider 用于离线运行。榜单页已能根据 scope 显示“联网榜”，但首页徽标和公共账号管理策略仍需随上线调整，不能只改文案就声称已联网。

后续联网版必须完成以下工作：

1. 确认部署平台、数据库与玩家身份方案。服务器绑定登录身份，不信任浏览器传来的 playerId。
2. 成绩按 `(playerId, levelId)` 唯一约束存储，事务性更新最好分。用关卡版本、幂等完成 ID 和服务器验证的挑战结果校验奖励；禁止直接相信客户端 flowers 或总分。
3. 公共查询返回最小公开数据（昵称、粗粒度地区、花数、名次），加分页与“我的排名”查询。地区仍手填，不要求精确地址。真实姓名不作为上榜必填项。
4. 多本机档案与公共账号之间的切换需新的授权流程；不能仅凭本机 ID 修改他人的公共分数。本地可改成绩不得自动导入可信公共榜。
5. 明确昵称审核、限流、隐私说明、删除账户、异常结果与重试策略；网络错误必须可见且不丢失训练结果。认证 Token/私钥不可硬编码进离线文件。
6. 公共榜单对分页和本地档案管理的 UI 需要适配，不把当前“本机多人存档”伪装为公共账号。
7. 离线 HTML 当前 CSP 为 `connect-src 'none'`，必须继续使用本地 Provider。另做联网发布配置时，按需允许自己的 API 域名，不随意开放所有网络来源。

## 验收命令

```powershell
pnpm test:leaderboard
pnpm test
pnpm typecheck
pnpm build
pnpm export:offline
```

排行榜自动测试覆盖校验、Unicode、非法分数、排序/并列/零分、旧存档迁移、玩家隔离、最好成绩幂等、当前玩家重置、存储异常、版本损坏保护、玩家数上限、顺序跨标签读写和新增/关闭关卡。UI 需另用浏览器检查；规则测试不等于真实手机验证。

手工验收：保留旧分数进入榜单 → 修改昵称/地区 → 新建另一玩家 → 完成一关 → 回榜单核对奖励 → 切回原玩家确认分数不变 → 刷新确认存档保留。分别检查 390px、320px 宽度与正常桌面视口，不得横向溢出。请勿为测试删除用户原有存档。
