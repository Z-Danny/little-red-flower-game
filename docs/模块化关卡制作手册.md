# 模块化关卡制作手册

版本：1.0 · 2026-09-08。读者：制作者、协作者与负责制作关卡的 AI。

## 1. 已交付的能力与边界

这不是把两关复制到更多文件夹：新关使用同一套 `configured-v1` 数据引擎，不认识“锅盖”“台风”等业务名称。防范类与处置类共享状态机、动画采样、透明轮廓判定、风险、暂停和结算；区别由 JSON 中的输入规则及剪影开关决定。

- 原《台风前的家》和《厨房着火了》继续使用已验收的专用表现适配器，保留电线跟随、窗锁、风雨、烟雾、人物动作等细节。本轮没有用模板画面替换原关。
- 原两关的图片路径和布局已抽到 `content/presets/typhoon/skin.json`、`content/presets/kitchen/skin.json`，改画风不用修改状态机。
- 新关可以配置任意稳定物件 ID、点击/拖放、前置条件、错误与无关行为、动作轨道、状态图与通关条件，不用增加 `if (levelId === ...)`。
- 通用特效当前包括火势放大和风险晃动；复杂流体、骨骼动画、拖拽拼装、连续长按不是已支持的玩法。需要这些时，应先扩展引擎并补测试，不能声称任意玩法只填 JSON 就能做。
- 示例包仅演示配置能力，复用现有素材，默认隐藏。它们不是已完成内容审核的新商业关卡。
- 蒙版提取与补空仍是独立试制规范，并非本次已经实现的自动生图流水线。

## 2. 目录与修改边界

```text
content/
  catalog.json                         新关清单：id、选用皮肤、是否开放
  presets/kitchen/skin.json             原厨房关图片、布局、相机安全区域
  presets/typhoon/skin.json             原台风关图片、布局、电源视觉锚点
  templates/prevention/                找隐患的可运行模板
  templates/response/                  处置类的可运行模板
  levels/<level-id>/
    level.json                         机制、目标、依赖、文案、风险、通关
    skins/illustrated.json              背景、状态图、布局、层级、动作轨道
    skins/<style-id>.json               同一套机制的另一套美术表现
public/levels/<art-pack>/              真正随包发布的 PNG/WebP
app/game/runtime/
  schema.ts                            数据接口与版本
  validate.ts                          字段、引用、可达性校验
  engine.ts                            纯状态机；不读 DOM，不按文件名判断
  scene.ts                             姿态与相机；绘制和反向点击共用
app/game/content/generated.ts          自动生成注册表，不手工改
components/game/configured/
  art.ts                               资源加载、透明像素缓存
  renderer.ts                          只绘制，不发放目标
  player.tsx                           输入、精简 HUD、暂停、结算
scripts/levels.mjs                      创建、批量、换皮肤、校验、启用、同步
tests/pipeline.test.ts                  通用机制、换皮肤不改规则与门禁测试
```

各关状态独立，缓存按完整素材清单区分。两个关卡使用同名 `lid` 不会共享已完成状态，也不会误用另一个皮肤的缓存。

## 3. 最常用：只换画风

### 原来的两关

1. 为待替换图片准备相同透明画布、物体方向、锚点与比例的图片，放到 `public/levels/<新画风包>/`。
2. 打开对应 `content/presets/*/skin.json`，只替换 `assets` 中的路径。资源键如 `lid`、`familyStanding` 不要改名。
3. 构图、物体大小或透明留白发生变化时，同时调整同文件的 `layout` / `placement`；厨房的 `cameraSafe`、台风电线接点 `powerVisuals` 也在此处。
4. 执行 `pnpm levels:check`、`pnpm test`，再实际试玩并导出。

**换图不等于任意构图自动对齐。** 原适配器仍有经过调试的专用动作：如果换成完全不同的房间结构、柜门方向或连接关系，需要校准专用表现层；不能只改路径后就宣称可用。原两关皮肤格式与通用 `skins/*.json` 有意区分，不可互换。

### 新的配置式关卡

```powershell
pnpm levels:skin --level example-response --id ink
```

得到 `content/levels/example-response/skins/ink.json`。把新图存进 `public/levels/...`，改此文件 `assets.*.src` 和必要的布局，保留 `level.json` 原样。检查通过后切换：

```powershell
pnpm levels:select-skin --id example-response --skin ink
pnpm levels:check
pnpm levels:sync
```

皮肤包含该规则需要的全部动画 ID 和物件 ID 才能通过校验。工具打印规则 SHA-256，验证报告也记录 `rulesHash`；可以比较换图前后哈希，确认机制文件没变。美术时长属于表现参数，约束在 0.5～1.5 秒；完成提交仍严格发生在动画结束后。

## 4. 新增一关或批量生成

在仓库根目录执行（不要在导出的 HTML 文件目录执行）：

```powershell
pnpm levels:create --id storm-bedroom --kind prevention --title 暴雨前的卧室 --order 9
pnpm levels:create --id stove-training --kind response --title 灶台应急训练 --order 10
```

ID 只能用小写英文字母、数字、连字符；编号 1～6 属于原训练册，7、8 已由示例包使用，新增编号必须唯一。命令只建立草稿，**不会根据标题自动生成对应知识、美术或正确规则**。

批量清单示例：

```json
[
  { "id": "storm-bedroom", "kind": "prevention", "title": "暴雨前的卧室", "order": 9 },
  { "id": "stove-training", "kind": "response", "title": "灶台应急训练", "order": 10 }
]
```

将其保存为 `production-jobs.json`，执行：

```powershell
pnpm levels:batch --file production-jobs.json
```

单关与批量示例是二选一，不要重复运行同一组 ID。命令一次支持最多 50 个草稿，先检查全表再落盘；重复 ID、非法目录、已有目录均拒绝覆盖。磁盘错误/断电可能留下尚未注册的新目录，应人工核对后恢复，不自动删除。

## 5. 机制配置方法

`level.json` 不含 PNG 路径，也不含屏幕坐标：

- `objects`：稳定 ID、标签和输入方式 `tap / drag / none`；`requires` 控制何时可操作，`disabledWhen` 控制哪些目标完成后禁用。
- `goals`：逻辑目标；防范类 3～6 个可见剪影目标。坐垫等辅助步骤可 `showTarget:false`，仍参与依赖和通关。全部目标最多 12 个。
- `interactions`：`source + mode + target` 对应一个行为。点击没有 `target`，拖放目标来自皮肤 `zones`。
- `requires`：必须全部完成；`unless`：任何一个已完成就不再匹配；`grants`：动作完成后发放哪些目标。
- `outcome:danger`：增加失误、风险、火势增强量，人物切到惊慌状态；`feedback` 只显示一处短提示。
- 无匹配规则：摇晃弹回，不扣分、不改变火势。正确操作不常驻动作字幕。
- `risk`：上升时长、初始值、警戒阈值和峰值短提示；达到 100 仍可继续。
- `completion.requires`：必须包含全部声明目标；全部完成后才播放收尾并结算。

示例：点击开关与先后皆可的锅盖。

```json
{
  "id": "shutoff", "source": "gas", "mode": "tap",
  "grants": ["gas-off"], "outcome": "correct", "animation": "shutoff"
}
```

撤离规则设置 `requires:["covered","gas-off"]`，不要让关火与盖盖互相依赖。规则按数组顺序匹配第一条可用项；复杂条件先写具体规则，再写宽泛规则。校验器会穷举目标组合，检查条件环、错误顺序导致的死路及被前面的规则挡住的正确操作。

## 6. 美术、动画与坐标契约

- `assets` 使用稳定资源 ID；`src` 必须在 `/levels/` 下，只接受 PNG/WebP。角色、道具必须 `alpha:true`，背景通常 `false`。
- `world` 是固定逻辑像素；`poses`、`zones`、关键帧都用同一坐标，不混入屏幕像素或百分比。
- `poses`：初始图片、矩形、`depth`、可选弧度旋转、透明度、0～1 的局部 `pivot`。depth 小先画、大后画；放好锅盖的 depth 必须高于锅。
- 静态遮挡物也可加入 `poses`。默认挡住点击；`blockInput:false` 适合火焰等前景特效。透明像素不挡住下方物件。
- `states` 按顺序覆盖姿态，支持 `all/any/not` 目标条件、`emotion` 和 `riskAtLeast`。人物惊慌/专注/安心图使用同样留白、尺寸与锚点。
- `animations` 每条含 `durationMs` 和若干对象轨道。关键帧 `at` 是 0～1，必须递增且末帧为 1；没有 0 帧，当前状态自动成为开始帧。`fromDrop:true` 表示从释放位置开始移动。
- 轨道可修改 x/y/w/h、rotation、opacity 和 asset。每次动画同一对象只允许一条轨道；状态换图在到达关键帧时生效。
- **动画末帧与完成后的状态必须一致**，否则下一帧会跳回。程序检查基本字段，不替代这个视觉验收。
- 剪影直接使用该目标初始图片变黑，不再另外绘制一套相似图标。
- 原图不是完整透明物体，或者裁切偏移发生变化时，自动校验无法猜测几何关系。先按[蒙版分层协议](蒙版分层关卡生产协议.md)验收母图、蒙版、补空和回贴。

通用相机采用等比完整呈现，极端比例允许边缘留白，优先不裁掉交互物件。想尽量铺满手机，应以目标手机比例制作背景；不能把横幅房间拉伸为竖幅。

## 7. 开放与导出

```powershell
pnpm levels:check
pnpm test
pnpm typecheck
pnpm dev
```

草稿要试玩时，在本地准备验收后执行 `pnpm levels:enable --id <id> --reviewed`，再 `pnpm levels:sync` 并重启/刷新开发服务。`--reviewed` 是制作者的验收确认，不代表程序能自动判断科普内容安全或美术优秀。

完成试玩后，若仍是样例或未审核内容，重新 `pnpm levels:disable --id <id>`。构建和导出会校验并同步注册表；不必修改首页、引擎或手写 import。

```powershell
pnpm build
pnpm export:offline
```

所有启用关卡的背景与素材会内嵌进一个 HTML；未启用样例不出现在正式关卡列表。更换 PNG/WebP 后必须重新导出，旧 HTML 不会自动读取源码目录中的新图。手机打开 20～30 MB 单文件需要资源与内存预算；大量关卡应按训练册分批导出，当前版本没有自动分册工具。

## 8. AI 的完成标准

1. 阅读本文件、模板和目标类型，先确认原关皮肤还是新关配置，不混格式。
2. 新主题先审核安全知识，再创建草稿；不能仅改标题。
3. 不修改公共状态机以适配单个物件名字；需要新机制时显式声明接口扩展并加测试。
4. `levels:check`、测试、类型和构建全部通过；输出有定位到 JSON 字段的失败信息。
5. 实际点击/拖拽检查：可见轮廓、透明边缘、遮挡、前置、动画中间帧、末帧、两种合法顺序、危险/无关反馈、暂停、风险到顶、重玩、结算。
6. 至少检查 320 与 390 宽的竖屏；实体设备与自动化模拟分开记录。不能把单元测试当成真实手机试玩。
7. 比较换皮肤前后规则哈希；检查没有重复物体、白边、拉伸、悬空、坐在插线板上等视觉错误。
8. 草稿审核通过才开放；保存素材来源与许可、提示词、规则版本和验收记录。
9. 新版离线文件实际加载确认无外部依赖；不要声称未测试的 file://、手机系统兼容性已通过。
10. 最终明确“已实现/已测试/未测试/仍需审核”，不把脚手架或生产规范写成已稳定量产。
