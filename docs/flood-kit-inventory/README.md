**接入状态：已按用户“加入关卡”的要求纳入主游戏本地离线版。沿用正式地图上的 `flood-kit`，未新增重复关卡；线上版本未发布。**

## 玩家流程

1. 七件候选物品都可点击装入，包括电视遥控器和陶瓷摆件；收纳动画结束后才提交背包内容。
2. 背包容量严格为5件；同一物品不能重复装入。装满后再点第六件只提示容量已满，不额外扣5秒。
3. 点击场景中的真实背包，或底部“背包 X/5 · 查看”，查看五格物品图像、名称和数量。任何已装物品都可取出，恢复到场景原位置，并清除它对应的收纳目标，允许重选。
4. 未装满时“确认出发”不可用。装满不自动通关，必须打开背包、主动确认出发。
5. 五件恰好为饮用水、即食食品、手电筒、收音机、救生哨，出发才进入原有结算；若混入一件或两件不需要的东西，立即失败，不发花。失败页列出错误物品、简短原因和缺少的正确物品。
6. 50秒倒计时保留，查看背包时继续计时，界面明确提示；暂停仍冻结。五件正确但没有确认出发也会超时失败。截止前接受的出发可完成结算，但最后一次装入动画不能替代出发。
7. 重试清空本局背包，所有物品回到原位；既有玩家成绩不清除，重玩不重复发花。

## 实现边界

- `Rules.inventory` 是可选的通用规则配置，定义容器、容量、候选物、正确物与失败说明；不通过图片名判断正确性。
- `Run.inventory`、`departed`、`inventoryRejected` 为本局状态。引擎负责容量、装入提交、取出、截止时间和出发判定；UI不能自行发奖或改变结果。
- 原五个正确物品目标ID、原五件收纳动画、场景构图、八个物件姿态（含背包）、资产文件及原通关奖励文案保持。两件干扰物改用与原物品一致的装包动画，不再在选择时直接告诉玩家“不需要”。
- 规则校验限制背包为无阶段、无互相依赖的点击收纳；正确物品的目标和禁用条件必须绑定自身。取出不会破坏其他关卡的单调目标规则。
- 共享 `InventoryControls` 复用原版纸纹和金色手绘按钮。五格显示真实物品，取出/出发按钮至少44px；支持键盘与Escape收起。抽屉打开时隐藏键盘辅助导航不可聚焦，避免焦点进入被遮挡的辅助层。
- 没有新增相机、关卡专用CSS、生成图片、AI朗读或语音。正式存档结构不变，不提交、不推送、不发布。
