# 台风前的家：整场景蒙版识别工作流

版本：2026-09-09。本文是当前台风关的执行契约，不代表其他五关已完成同样改造。后续 AI 必须先读本文，再读实际配置、状态机与测试，不能根据旧截图猜实现。

## 1. 本轮最终验收标准

- 只改《台风前的家》；保留厨房和文字稿首批四关、本机排行榜及原有存档。
- 隐患与室内背景来自一次完整绘画。不能把另外生成的花盆、窗户等贴回房间。
- 顶部五个剪影从这张原画按蒙版提取。点击区域由同尺寸 ID 蒙版决定，不用宽泛矩形热区。
- 点击只播放 800 毫秒红圈描画，隐患不移动、不消失、不变安全。禁止恢复旧版“搬花盆、拔插头”的过程动画。
- 找齐五项才展示规范处置后的完整效果图，再结算 3 朵花。红圈表示识别，不表示现实隐患已处理。
- 90 秒为风雨演出增强时间，不是死亡/救援倒计时。到顶仍可寻找；误点不扣分。
- 音频只有原创合成音乐、风雨和交互音效。**禁止 AI 朗读、speechSynthesis、TTS 录音和自动念提示语。** 此项为用户最新反馈，优先于先前“加入人物语音”的要求。
- 所有雨层在人物后面；不在脸上叠加雨滴或汗滴。禁止以增加危机感为由破坏遮挡关系。
- 不增加步骤答案板、常驻操作说明、重复提示。顶部只保留关卡、时间、暂停和五个剪影；提示为短暂单条字幕。
- 保留单文件离线能力，不引入 CDN、在线音频、字体或分析服务。

## 3. 生产步骤与停线条件

### A. 内容先审核

列出每个目标为何危险、现实中何时处理、错误点击是否有真实含义。当前训练是“识别事前准备缺失”，不是让儿童在暴风雨中操作电器。未知/有争议的内容不得编造成事实；删除模糊说法或提出具体问题。

内容核对来源（2026-09-09 查阅）：[应急管理部：台风来了如何应对](https://www.mem.gov.cn/kp/zrzh/202208/t20220809_419856.shtml)、[家庭用电安全](https://www.mem.gov.cn/kp/shaq/201904/t20190403_365937.shtml)、[插座安全](https://www.mem.gov.cn/kp/shaq/202010/t20201023_370853.shtml)。采用提前收回阳台物品、关好门窗、避免湿手接触带电设备等常识；不采用“贴胶带即可防碎”“已经进水还靠近拔插头”等误导表现。

### B. 先画含全部隐患的完整原图

一次画出房间、人物、全部目标和装饰物。统一镜头、纸纹、光源、接触阴影和物理尺度。当前画风为暖色纸纹绘本，青绿色门窗、暖木地板。目标应有足够面积，避开顶部 UI 和底部字幕区。

必须人工看图：插座只能在墙上，不能画到沙发上；插线板电线要有合理去向；柜门与抽屉可区分；不能出现无意义重复雨伞；每个目标恰好一处。首张出现“插座在沙发上”时，本轮用局部编辑纠正后才进入下一步。

### C. 同构蒙版，不重新摆放

以已批准原图为输入，输出相同尺寸、不改变镜头/物体位置的平涂语义图。颜色契约：黑=不可点击，红=花盆，绿=敞开窗门，蓝=晾衣杆及衣物，黄=插线板，品红=柜门，白=母子（仅供分离动画，不是目标）。

AI 蒙版仅是候选，**相同尺寸不等于精确配准**。逐个叠加检查位置与遮挡，必要时修正。窗门玻璃区域允许填充以便手机点击；剪影仍保留中空门框，不能变成通用黑矩形。目标颜色绝不能交叠。背景抗锯齿和近似颜色必须量化为唯一 ID。

### D. 仅提取人物并补人物底图

从原图按人物蒙版提取原像素；本轮通过 GrabCut 边缘细化生成真透明 PNG。单独生成“只移除人物”的同构底图。程序只允许修改人物原位置及少量边界，且所有目标蒙版区域强制保留原始像素。不可用整块新背景盖住隐患，也不可把人物重新画成另一种画风。

本轮机械脚本：`python scripts/prepare-typhoon-scene.py`。依赖 Python、Pillow、numpy、scipy、opencv-python。普通玩家运行不需要 Python；仅重新加工素材时需要。输入原图 941×1672，统一处理到逻辑画布 720×1280。

输出必须检查：透明通道存在、无棋盘格、无白边/黑边、人物脚底不漂浮、原位置无明显残影。`family-proof.png` 只是静态重组证明，不是浏览器试玩。

### E. 单独生成完整安全效果图

保持构图、家具尺寸和光影风格；花盆搬入室内，门窗关好，晾衣物收回，插线板断开收妥，柜门闭合且高柜固定，家人在沙发上平静坐下。外面仍可有雨，不能暗示整理房间能令台风立刻消失。效果图不参加目标命中，只在全部找到后切换。

### F. 配置与渲染顺序

所有屏幕输入先经 `camera()` 逆变换，再读取 ID 蒙版像素。采用 contain 完整显示；禁止 cover 裁掉目标。目标 ID 与规则、图标、颜色必须一一对应。`checkHunt()` 验证尺寸、时长、颜色、范围和本地路径。

绘制顺序固定：完整底图 → 窗外天气/门口少量飘雨 → 原画人物及脚底阴影 → 红圈/误点反馈 → 整幅安全效果图 → UI。**雨先画、人后画**，不要把全屏粒子覆盖在人脸上。人物使用同源透明画面的分条形变实现呼吸、倾身和紧张轻颤，不是完整骨骼动画，也不是独立表情序列。

标记 800ms 后才提交 found，重复点击/忙碌时点击不会重复提交。5/5 后 800ms 留观，再用 1800ms 交叉淡化安全图，5500ms 时结算。风险满格绝不能跳过目标或阻止完成。测试全部 120 种顺序。

### G. 音频与页面生命周期

只在用户点“进入场景”后创建/恢复 AudioContext。风、雨、紧张音乐随同一个 pressure 增强；找到、误点、雷声、解除、结算各有独立音效。安全效果阶段降低风雨并换舒缓音列。提供静音与音乐开关，无 AI 朗读开关。

暂停/切后台必须同时停计时并压低总音量；返回页面保留用户的静音设置；退出组件 stop 所有声源并 close 音频上下文。禁止留着测试标签页持续播放声音，测试结束立即关闭。音量波形非零只证明音频图输出，不证明扬声器听感已验收。

## 4. 验证顺序

```powershell
pnpm test:scene-hunt
python scripts/check-scene-hunt-art.py
pnpm test
pnpm typecheck
pnpm build
pnpm export:offline
```

像素检查读取真实输出，不只信生成报告：场景/安全图/蒙版同尺寸；五种颜色都有像素；所有隐患原画像素在人物补空后保持不变；人物和剪影是真透明。

可选静态渲染：安装已有受信任的 `@napi-rs/canvas` 后运行 `node scripts/render-scene-hunt-qa.mjs`，也可把本机已安装的包路径作为第一个参数。它直接调用生产 renderer 导出初始、满风险、全红圈、安全四帧，**不启动浏览器、音频或服务**。不能替代触屏/音频实测。

浏览器验收清单：390×844、320×740、桌面；起始零进度、五个实际像素命中、空白不增加目标、连续点击不重复；0.8 秒描圈；90 秒峰值仍可通关；人物脸前无雨；暂停计时/静音、返回、重玩；安全画面至少完整展示后结算；重复通关不刷榜。除非拿到直接证据，禁止把“单元测试通过”写成“真机验收通过”。

单文件导出内嵌所有实际引用图片，不打包朗读文件。CSP 保留 `connect-src 'none'`。本地 file:// 与本机 HTTP 是两个不同验收环境；其中一个通过不能代替另一个。

## 5. 批量复用边界

当前脚本和 renderer 是经过这一关验证的首个模板，不是任意主题的一键成品。批量新关需要新增独立 rules/skin，复用状态机与输入判定；主题特有天气/人物锚点必须审核。不要把“所有关都是台风、都叫五个目标”写进新关。

仅换画风：不改目标 ID/状态机/奖励；重做同构场景、蒙版、同源人物、底图和结局图，更新 skin，然后重跑所有验收。改变目标或机制：必须新增测试并明确是否仍属于识别类，不能偷偷改变旧关存档 ID。
