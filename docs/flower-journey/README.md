# 三张安全地图与小红花旅程

当前分类按用户指定的三类主题组织：自然灾害、公共安全、居家校园办公，分类名称均不带“应急”。三张独立地图分别包含 8、4、4 个可玩关卡，原关卡 ID、互动规则、蒙版与存档保持稳定。地图是可上下探索的完整插画，不把关卡矩形卡片叠在背景上。

区域名与“小红花应急行动”位于同一条顶部栏。每张图从下方第一关出发，沿路线向上推进；进入区域时定位到当前可玩的节点。关卡名称沿用原名，地点对应通过重画地图和调整实际落点解决：街口在斑马线附近，电梯在玻璃电梯入口，井口在真实圆井与围挡旁的安全路面，家庭关在住宅入口。

## 修改前核查：六个问题

| 检查项          | 真实基线代码中的情况                                                             | 本轮改动                                                                              |
| --------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1. 地图还是列表 | `components/game/level-hub.tsx` 是普通关卡卡片列表；无场景节点或地图镜头         | 三张独立场景图，节点、花位和道路嵌在地图中                                            |
| 2. 花朵是否存档 | 是。`use-leaderboard` → `local-provider` → 本地存储，原先按关卡最好成绩记 1–3 花 | 增加首次完成领取接口，首次固定 3 花；重复领取为 0                                     |
| 3. 通关闭环     | 各引擎有自己的结算和部分安全结果图，缺少公共返图、飞花、种花与解锁演出           | 650ms 安全画面 → 共用结算 → 返图飞花、花芽展开、开花、计数、引导                      |
| 4. 三种状态     | 只有可玩与草稿等分类，没有基于当前玩家进度的连续解锁                             | 灰色花苞、小锁与薄雾 / 微光花苞 / 盛开花朵与完成标记                                  |
| 5. 刷新保留     | 花数、已完成最好成绩已有持久化；不存在需要持久化的玩家解锁状态                   | 仍用原存档。解锁从已完成 ID 推导，刷新保留；中断种花动画也不丢奖励                    |
| 6. 手机竖屏     | 已有统一关内视口；首页是长列表。不能仅凭代码宣称所有手机无溢出                   | 增加地图与结算多尺寸浏览器检查，结果见 verification/browser-report.json；实体手机未测 |

核对范围：`app/page.tsx`、`game-app.tsx` 的状态路由、`app/game/levels.ts` 的关卡目录、四类播放器和状态机、`app/game/leaderboard/` 及本机榜。并阅读了 `docs/hunt-pipeline/AI_START.md` 和 `README.md`。当前是本机存档与本机排行榜，没有新增后端、账号或线上排名。

## 经常要改的内容

三类主题、顺序、说明及所属地图由 `content/journey-categories.json` 独立管理。地图标题在 `journey-map.json` 的 `name/short` 中同步配置。分类不参与存档键，也不改变原关卡 ID。

主题范围：自然灾害涵盖地震、火灾、洪涝、台风及极端天气等避险自救；公共安全涵盖拥挤踩踏、交通出行、电梯/地铁故障、燃气/用电安全等；居家校园办公涵盖防火防电、厨房、实验室及独居防护等。上述为内容组织范围，当前开放关卡仍为已有的 16 关，不代表所有主题都已制作完成。历史五类版本的验收记录保留其当时的文件指纹，当前分类以本配置为准。

| 要改什么                   | 文件                            | 字段或做法                                                                                                                       |
| -------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 三张地图图片               | `content/journey-map.json`      | 每个区域的 `image`；实际文件放在 `public/levels/` 下                                                                             |
| 地图区域名称、奖章名       | `content/journey-map.json`      | `name`、`short`、`medal`                                                                                                         |
| 关卡显示名称               | `content/journey-copy.json`     | `levels.<固定 ID>.title`；地图、介绍、关内标题、结算、排行榜共用                                                                 |
| 简短事件介绍               | `content/journey-copy.json`     | `levels.<ID>.preview`；空字符串沿用原关卡介绍                                                                                    |
| 花朵、花丛、花苞、锁定素材 | `content/journey-skin.json`     | `flower`、`restorationFlower`、`bud`、`locked`；当前使用透明插画花苞，`locked` 为空时叠加小锁并降低饱和度                        |
| 节点位置、顺序             | `content/journey-map.json`      | `nodes[].x/y` 为花坛接地处的画布坐标；文字独立放在下方；数组顺序决定逐关解锁，y 从大到小向上推进；`place` 记录对应地物供维护使用 |
| 恢复后的花径、灯光落点     | `content/journey-map.json`      | `restoration.flowers[]`、`restoration.lights[]`，与节点相同坐标系                                                                |
| 画布比例                   | `content/journey-map.json`      | 每个区域的 `width/height`；自然图 720×1800，另外两图 720×1280；节点、道路、镜头和恢复装饰共用区域坐标系                          |
| 动画阶段时间               | `content/journey-timing.json`   | 毫秒单位，结算、音效、四类播放器和地图读取同一配置                                                                               |
| 科普总结和出处             | `app/game/journey/knowledge.ts` | 按固定 ID 的 `summary/publisher/url/result`；改动需要重新核查来源                                                                |
| 样式尺寸和色彩             | `app/garden.css`                | 仅地图、公共弹窗及种花演出；不会覆盖关内统一视口                                                                                 |

例如，把厨房关显示名改为“厨房里的紧急时刻”：

```json
"oil-fire": {
  "title": "厨房里的紧急时刻",
  "preview": "油锅冒起火苗，先观察哪些操作能让它安全下来。"
}
```

`oil-fire` 是存档和玩法使用的固定 ID，改名时不要改它。换图不会改变点击规则；地图节点的可点击区域由节点配置决定，关内素材和点击蒙版仍由原找隐患/处置流水线管理。

换图步骤：把新图放进 `public/levels/你的目录/` → 修改上述路径与区域画布比例 → 按关卡实际地物入口调整节点和花径坐标 → 执行 `pnpm test:journey`、`pnpm typecheck`、`pnpm export:offline` → 打开导出的 HTML 检查。支持当前离线导出器已有的 PNG/WebP 路径；不要把远程 URL 或本机绝对磁盘路径写进图片配置。五项正式素材、完整生成提示词、尺寸与 SHA 记录在 `art-prompts/asset-manifest.json`，地物落点说明见 `art-prompts/semantic-node-manifest.json`。素材为本轮生成的原图，没有裁切或重绘他人游戏素材。

修改公共显示名称不改规则、录音或画面内已有的文字。如果还要修改规则解释、目标名称或声音，请走原关卡流水线相应的文案/演出文件，避免显示文案和安全知识脱节。

## 模块职责

- `app/game/journey/progress.ts`：无 UI 的节点状态、解锁、花数和区域完成计算。
- `app/game/journey/categories.ts`：主题与地图关联、空类别状态、分类完成统计；没有关卡的类别不会获得奖章。
- `app/game/journey/presentation.ts`：读取素材、名称与时序配置，不写存档，不改变关卡规则。
- `app/game/leaderboard/model.ts` / `local-provider.ts`：首次领取、旧档兼容、玩家隔离和持久化；无法写入时明确提示临时记录。
- `components/game/game-app.tsx`：地图、关卡、结算、本机榜之间的状态路由；绑定开始关卡时的玩家 ID。
- `components/game/level-hub.tsx`：只组合地图各模块。
- `journey/map-scene.tsx`：场景、节点、道路与恢复装饰。
- `journey/map-chrome.tsx`：必要导航、花数和区域选择。
- `journey/use-map-journey.ts`：地图镜头、动画进度和计数，切后台冻结；减少动态效果偏好单独处理。
- `journey/level-entry.tsx` / `archive.tsx` / `settlement.tsx`：介绍、长期档案、共用结算。
- `journey/flower.tsx` / `safe-feedback.tsx` / `reward-sound.ts`：共享素材、场景内成功提示、轻量奖励音效。

上述 `journey/` UI 相对 `components/game/`。原有四套玩法状态机仍负责判断成功；公共模块只接收成功回调，不根据按钮点击、播放动画或打开结算直接发奖。未完成、失败、提前撤离没有新奖励，也不解锁下一关。草稿不进入地图。

## 奖励与演出约定

首次完成先保存 3 花，再展示结算。已完成旧关（包括旧版 1/2 花记录）保留原花数，重玩不补发、不重复加总。每关花坛的一朵主花表示“完成一关”，钱包三朵表示累计奖励，含义不同。

安全结果停留 650ms；结算三花按 180ms 间隔开放。点击返回后，650ms 飞花到达，850ms 左右进入花芽展开，1350ms 开放，1550ms 钱包计数，1850ms 道路与环境恢复，2150ms 开始轻移到下一节点，2600ms 结束。自动演出约 3.79 秒，不计玩家阅读结算的时间；不强制进入下一关。每区域第一关独立开放，后续按区域顺序解锁。

找隐患关的安全图是另一时点规范处置后的示意，不把“识别”表述成现实中已修复。电梯与井口仍是安全待援；洪水结局仍须等待救援，不暗示积水可通行。

知识来源逐条使用官方网页或文件核对并简短转述，结算提供原始链接。来源检查不代表官方认证本游戏。具体摘要和 URL 以 `knowledge.ts` 为准。

## 验证与本地交付

`tests/journey.test.ts` 覆盖目录对应、配置素材、逐关解锁、首次奖励幂等、旧档、两实例领取、玩家隔离与存储失败。`scripts/test-journey-browser.mjs` 使用隔离的 Edge 上下文与真实鼠标/触屏输入，不注入完成标记或花数；自动验证全部 16 关、重玩、刷新、锁定、未完成/失败、区域恢复、奖章、不同玩家与减少动态效果。运行结束关闭测试浏览器，声音硬静音。

```powershell
pnpm test:journey
pnpm test:journey-browser
pnpm typecheck
pnpm build
pnpm export:offline
pnpm preview:journey
```

浏览器脚本可用 `PLAYWRIGHT_PATH` 与 `EDGE_PATH` 环境变量指定已安装的运行时；默认路径是本次 Windows 验收环境。未下载依赖，未发布网站。完整结果、最终离线 HTML SHA 与尚未进行的实体手机/人工听音检查见同目录验收记录。

`preview:journey` 仅监听本机 127.0.0.1:8087，使用同份代码、导出样式和本地素材，避免把大体积内嵌图片塞入开发预览。实际离线 HTML 仍包含完整图片与音频，无需服务或网络即可运行。
