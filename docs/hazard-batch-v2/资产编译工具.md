# 五目标整场景资产编译工具

版本：2026-09-10。适用于本批新关，不修改旧关素材或引擎。

## 已执行的验证

- 两个 Python 脚本语法编译通过。
- 内置隔离合成夹具自测通过：5 色像素、透明来源、补空保护、效果遮罩、首次编译、同 SHA 草稿刷新、历史备份、已批准锁拒绝覆盖。
- 自测使用临时几何图，不是实际关卡原画。实际原画、结局、视觉配准、手机辨识、浏览器与声音均不因此通过。

## 文件

- scripts/prepare-hazard-batch.py：生成素材、skin 与证明文件。
- scripts/check-hazard-batch-art.py：只读像素检查，不产生审核批准。
- 依赖：Pillow、numpy、scipy、opencv-python。沿用旧 prepare-scene-hunt.py 的原像素提取与受限补空方法，补充五色、批量路径、可配置修正与可恢复刷新。

## 输入契约

每关目录：art-source/hazard-batch-v2/Hxx/，包含：

1. scene-original.png：已视觉认可的完整原画。
2. mask-candidate.png：与原画同尺寸、同构图，五目标红绿蓝黄品红，人物白、其余黑。
3. clean-candidate.png：移除人物后的候选底图。脚本只取许可区，不把整张候选直接当底图。
4. ending.png：同尺寸完整结果图。
5. production.json。

四图必须尺寸相同。输出统一 720×1280；原图与结果使用 Lanczos，蒙版使用最近邻。近色容差仅用于候选分类，运行 PNG 是精确 RGB。

~~~json
{
  "id": "clear-corridor",
  "authorId": "H06",
  "sourceSha256": "原画真实SHA256，大小写均可",
  "world": [720, 1280],
  "output": "public/levels/hazard-batch-v2/clear-corridor",
  "skin": "content/scenes/clear-corridor/skin.json",
  "targets": [
    {"id":"blocked_path","color":[255,0,0]},
    {"id":"ebike_charging","color":[0,255,0]},
    {"id":"wedged_fire_door","color":[0,0,255]},
    {"id":"locked_exit","color":[255,255,0]},
    {"id":"blocked_hydrant","color":[255,0,255]}
  ],
  "corrections": {
    "targets": {},
    "characters": {}
  },
  "effects": {
    "weatherPolygons": [],
    "waterPolygons": [],
    "skyPolygons": [],
    "firePolygons": [],
    "smokePolygons": [],
    "fireSources": [],
    "smokeDrift": 1
  }
}
~~~

id 必须与 output、skin 子目录一致，作者 Hxx 不直接等于运行关卡编号。脚本不能写到批次以外的输出，不允许覆盖既有 skin。没有环境效果的关卡仍输出全黑效果 mask 文件供 QA，但不会把这些未授权效果路径注册进 skin。

## 多边形修正契约

所有多边形为逻辑坐标，格式 [[[x,y],[x,y],[x,y],...], ...]；每个至少三点，闭合隐含，不允许越出 720×1280。不能直接填原始大图像素坐标。

~~~json
{
  "corrections": {
    "targets": {
      "blocked_path": {
        "keepPolygons": [[[10,300],[300,300],[300,700],[10,700]]],
        "excludePolygons": [[[10,300],[40,300],[40,330],[10,330]]],
        "fillEnclosedHoles": false,
        "reason": "审核后仅保留纸箱实体，排除误涂墙面"
      }
    },
    "characters": {
      "keepPolygons": [],
      "excludePolygons": []
    }
  }
}
~~~

- keepPolygons 非空时，把候选分区裁进多边形并集；空数组或省略表示不裁。
- excludePolygons 从分区删除；删除优先于封孔。
- 人物 excludePolygons 同时禁止修补与微动覆盖，用于原画前景桌面、植物、水杯等静态遮挡物；避免 alpha 膨胀和补空边界把刚排除的物件再次带入。
- fillEnclosedHoles 仅适用于原实体内部被漏涂的实心部分，必须有 reason。实体孔洞例如椅腿空隙不能填。此项同时改变实体蒙版与图标来源，只能看图后使用。
- 若实心物体的候选轮廓有 1～3px 漏缝导致孔洞与背景连通，可在已有 fillEnclosedHoles 和 reason 时增加 closeGapsPx（整数 0～3，默认 0）；先进行该尺度闭合再填内部，且不扩原包围盒。仅用于看图批准的实心内部，禁止亭柱、球车或椅腿自然空隙。H12 烟灰盘使用 1px；不是通用提高手感开关。
- 不支持凭矩形直接新增目标。原图没有的物体必须退回生图。
- 仅获得卡片许可且看图审核过的亭体空隙可用 hitFillPolygons；必须有 reason，只能在实体包围范围内，且不能覆盖其他目标或人物微动范围。它只扩大 id-mask，不改变 object-mask 和剪影。
- 上述坐标仅为语法示例，不能直接用于 H06 真图。
- 所有 corrections 都写入 processing.json，便于追溯。程序不证明“被删掉的确实是墙面”，语义还需看叠色图。

## 人物与补空

1. 白色人物候选经原图 GrabCut 精修，固定随机种子；不会生成陌生脸或新衣服。
2. family.png 的 RGB 来自原画，alpha 是真正透明，familyBox 由原像素分区推导。
3. 目标保护区为五个实体目标并集扩 3px。
4. 只允许人物分区和白色候选周边最多 10px 的补空，减去目标保护。候选底图只在此区合成，外部像素强制来自原画。
5. character-mask.png = family alpha 可见区扩 15px，再减目标保护及人物 excludePolygons。人物排除区也不准补空。这个 mask 是微动允许范围，不是人物自身 alpha，也不参与目标命中。
6. proof/repair-mask.png 是实际软 alpha；repair-allowed.png 是硬许可区；target-protection.png 是目标保护；family-alpha.png 是全画幅可见人物二值来源。
7. 必须看 reconstructed.png 检查发丝白边、裁切、旧人物残影和脚底。像素保护成功不能证明抠图美观。

## 环境契约

effects 的五组 Polygons 分别批准雨、涟漪、云层、火、烟的渲染范围。实际二值 mask 一律再扣：

- 所有命中目标的 3px 保护区（包括获得批准的亭体 hit 填充）。
- 人物 characterMask 微动允许区。

这样效果不能压住人物，也不能用半透明大矩形遮住目标证据。注意：火源载体在目标保护区，火焰应生长到载体上方批准空气区；fireSources 的矩形至少要与生成后的 fireMask 有有效交集，否则报错。禁止为让火能画在人物上而取消扣除。

~~~json
{
  "effects": {
    "firePolygons": [[[100,300],[170,300],[170,450],[100,450]]],
    "smokePolygons": [[[80,180],[190,180],[190,420],[80,420]]],
    "fireSources": [
      {"kind":"flame","x":110,"y":320,"w":50,"h":100}
    ],
    "smokeDrift": -1
  }
}
~~~

fireSources.kind 仅支持 flame、ember、fountain。x/y/w/h 均为逻辑坐标中的批准效果框，不是自动计算的风险大小。smokeDrift 只允许 -1 或 1，必须先确定风向不会吹向人物。代码不推断现实火势增长或安全距离。

skin.effects 只注册拥有非空批准多边形的效果。characterMask 始终存在；无火关不注册 fireMask、smokeMask、fireSources、smokeDrift，室内关无天气多边形时不注册任何天气路径。火场必须同时给出非空 firePolygons、smokePolygons、fireSources，少一组即拒绝编译。扣除人物和目标后完全空的已申请效果也会报错，不能用空 mask 伪通过引擎许可。

室内关生成的 skin.effects：

~~~json
{
  "characterMask": "/levels/hazard-batch-v2/<id>/character-mask.png"
}
~~~

雷雨关只增加获得许可的 weatherMask、skyMask、可选 waterMask；火场关只增加 fireMask、smokeMask、非空 fireSources 与 smokeDrift。引擎仍根据 performance.atmosphere 严格校验，编译脚本不放松引擎规则。

## 执行

在项目工作副本根目录运行：

~~~powershell
python scripts/prepare-hazard-batch.py art-source/hazard-batch-v2/H06/production.json
python scripts/check-hazard-batch-art.py art-source/hazard-batch-v2/H06/production.json
~~~

候选蒙版完善后，原画 SHA 不变且尚未批准的草稿：

~~~powershell
python scripts/prepare-hazard-batch.py art-source/hazard-batch-v2/H06/production.json --refresh
~~~

刷新要求输出包含本工具 .compiler-owner.json，身份和原图 SHA 相同，skin 未被外部改动。旧草稿输出和 skin 保存到该卡 compiled-history/，不删除旧关。先在独立临时构建目录验证完才提交；构建失败不会留下半成品正式输出。

锁定：批准后在输出目录、卡片原稿目录或 skin 所在目录放 APPROVED.lock 或 .asset-approved，之后编译与刷新都拒绝。也可设置 production.json 的 outputApproved=true，但这会改变 spec SHA，若要后续只读 QA，推荐使用锁文件。不要把“原画已认可”误设成 outputApproved；输出批准应在素材、程序验收全部完成后。

只读 QA 不受锁文件阻止。它会发现输入文件或 spec 在编译后改动，应重新编译草稿而不能手改报告为通过。

独立工具自测：

~~~powershell
python scripts/check-hazard-batch-art.py --self-test
~~~

自测只在临时目录构造几何夹具并清理，不读取或改写真实关卡图。

## 产物

- 输出包：scene.webp、clean.webp、ending.webp、family.png、object-mask.png、id-mask.png、五个目标 id.png、六个效果/人物 mask、hit-samples.json、.compiler-owner.json。
- 自动 skin.json：路径、720×1280 尺寸、人物框、逐目标源 bounds/color/icon、effects 配置。
- 卡片目录：processing.json（输入输出 SHA、修正、像素计数、保护断言）、hit-samples.json、proof/各目标叠色图、总叠色图、重组图、各保护证明。
- hit-samples.targets 是每个真实 object-mask 内的最大欧氏距离点，不是外接矩形中心，也不是填充亭体孔洞里的点。background 来自非目标且非人物的空白区，并避开上下 HUD 带；仍需浏览器确认可见可点。
- 图标用原图对应像素与真实 alpha 提取，保持比例并留 2px 透明边。渲染器需要单色剪影时应仅使用这些 alpha 轮廓，不另行生图。

## QA 实际检查项

- 恰好五目标、五种指定 RGB 和黑色背景；ID 图不存在白色人物或猜色。
- 原图归一后与 scene.webp 完全一致。
- clean 在目标保护区和实际 repair alpha 为 0 的位置逐像素不变；并验证底图确实按 repair 与候选合成。
- family 可见 RGB 来自原图，真 alpha；familyBox 与实际裁切一致。
- icon 与原图/object-mask 机械提取结果一致，真透明而非白底。
- 实体不是实心外接矩形热点；hit 的额外区只能来自明确 hitFillPolygons。
- 效果 mask 来自批准多边形，且不覆盖目标和人物；characterMask 等于 alpha 扩 15px 减保护。
- 样本点在真实实体且为最大内部距离位置；全部生成文件 SHA 一致。
- 结果不同于原图，但结果语义和构图一致性仍需人工/视觉复核。

返回 pixel_structure_pass 只表示上述像素结构通过，不表示真实关卡已可玩、已实际听音或通过手机验证。
