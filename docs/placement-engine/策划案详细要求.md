# 放置测试引擎 V2：策划案详细要求

你可以提交一份包含多关的自然语言策划案。由 Codex 先核实情境与处置逻辑，整理成生产卡，再用引擎编译、逐关检查、生成可离线试玩的 HTML。离线工具接收 `.json` 生产卡或关卡包；它本身没有连接语言模型，不能直接把任意 Word/PDF 自动理解成关卡。

## 1. 每批都要说明

| 内容 | 需要明确的要求 |
| --- | --- |
| 批次 | 关卡数量、编号、主题；单批 1～20 关，内嵌图片后的 JSON 不超过 64 MB，过大则分批 |
| 受众 | 年龄、知识基础、操作难度、目标设备；是否需要点选按钮辅助拖拽 |
| 美术基准 | 参考图、画风、视角、轮廓、纸纹、色温、饱和度、光源、人物服装；明确不能改变的内容 |
| 音频基准 | 是否需要环境音、每物品的材质、动作声音、触发时刻、音量；是否提供自有授权录音 |
| 交付 | 每关生产卡、放置配置、可试玩 HTML、音效文件与对应表、检查报告、实测截图 |

只有标题、故事和一句“拖到正确位置”不足以生产。下面的游戏逻辑必须写清；逻辑坐标与技术字段可由 Codex 根据画面补充，无需你手工编程。

## 2. 每关必填

1. **基本信息**：唯一编号、标题、地点、关卡类型、学习目标、建议时长、通关总结。
2. **初始事实**：人物在哪里，危险从哪里来，物品放在哪里，哪些道路/开关可达，是否有燃气异味等影响处置的重要条件。缺失的安全事实不能靠 AI 随意假设。
3. **成功条件**：逐条列出目标，哪些必须完成、哪些可以交换顺序、何时才记为完成。默认动画结束后提交目标。
4. **阶段**：每阶段的进入条件、结束方式、时长、可用动作、未完成处理。固定时长和“建议用时”必须区别；12 秒训练阶段不是地震真实持续时间。
5. **错误与恢复**：错误操作具体后果、扣分、反馈、回位/中断、能否重新操作。不能因一次错误永久卡死；涉及重新练习时，要写明触发条件。
6. **常理与来源**：安全教育提供官方来源链接，标明适用场景。关卡的训练步骤不能被写成现实中所有场景的强制条件。

## 3. 每个物品必填

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| ID 与名称 | `cushion` / 坐垫 | 名称可改，稳定 ID 用于引用 |
| 交互方式 | 拖拽、点击、长按、不可交互 | 长按须写持续时间、松手/移开/暂停/失焦如何处理 |
| 初始状态 | 沙发上、可拿起、未使用 | 必须说明支撑关系，避免悬浮 |
| 视觉规格 | 浅绿织物坐垫、透明背景 | 互动对象不能同时烘焙进背景形成重复物品 |
| 成功操作 | 拖到人物头颈部 | 指明接收对象与接触位置 |
| 条件 | 仅震动阶段可用 | 写明目标依赖、阶段限制、完成后是否禁用 |
| 最终状态 | 贴住头颈并随人物移动 | 写明位置、朝向、大小、前后层级、是否跟随 |
| 错误/无关操作 | 放到地面则回位 | 说明反馈与可恢复性 |
| 对应声音 | 织物拿起声、护头摩擦声、回位摩擦声 | 每物品都要填写下述声音表 |

## 4. 每个交互是一张完整动作卡

推荐格式：

> 动作编号｜当前阶段｜操作物品｜点击/拖放/长按｜接收区｜前置目标｜禁止条件｜正确/危险/无关｜动画时长｜路径｜最终姿态｜提交目标｜反馈文案｜动作音效及触发点｜失败后的恢复

例如 E07 的“抓牢”：

> `hold`｜震动中｜桌腿｜持续按住 1500 ms｜桌腿可见区域｜已伏地到桌下｜震后不可执行｜正确｜确认演出 500 ms｜原地｜低姿握住桌腿并保持｜held｜“保持低姿，等待晃动停止”｜手接触木头声；确认演出 85% 触发｜提前松开、移出、暂停或失焦均取消本次累计。

不要遗漏“拿起但取消”“拖到无关位置”“前置条件不足”“正确目标完成后重复操作”等分支。禁用物品不会再接受交互；能接受的交互都应有明确反馈。

## 5. 坐标和画面生产要求（由 Codex 落实）

- 统一逻辑画布；左上为原点，X 向右、Y 向下。E07 使用 720×1280，显示与输入均等比映射。
- 每物品分别定义**初始框、判定锚点、接收区域、最终落位、动画路径**。鼠标松手位置不是最终姿态。
- 同一物品的多个动作共用一个判定锚点。不同目标区域不重叠；禁止用隐形超大热区掩盖坐标错误。
- 图像透明留白可以通过 `assets.*.frame` 指定原图精灵帧，绘制与透明像素命中使用同一帧；原图不被改写。
- 覆盖关系必须写清楚：桌面盖住人物头顶，手接触桌腿，锅盖压在锅口上，人物脚底接地。几何框检查不能代替实际看图。
- 跟随物要按人物状态配置相对位置：站立与跪伏时头颈位置不同，不能只用一组偏移。
- 环境音与动态由阶段配置控制；普通归位关不能继承火焰、烟雾或厨房音效。

## 6. 音效硬性要求

每个可交互物品必须配置 `pickup / miss / blocked / return` 四项；每个动作必须配置 1～6 个声音触发点。无关动作也不能缺音效。装饰物 `input:none` 不必配置物品音效。

| 事件 | 应播放什么 | 不应出现 |
| --- | --- | --- |
| 拿起/按下 | 与物品材质匹配的短接触声 | 所有物品共用一个万能滴声 |
| 正确操作 | 接触、盖合、旋钮、脚步、穿鞋等具体动作声 | 物品还没到位就发出落位声 |
| 错误操作 | 对应风险声＋必要的低强度提示 | 自动接“成功”声、持续刺耳警报 |
| 条件未满足 | 可区分的短阻止反馈 | 完全静默或装作已成功 |
| 取消/回位 | 回位时对应材质声 | 声音与画面分离，暂停后仍不断播放 |
| 阶段变化 | 按需设置震动低频声、停止后的提示 | 把环境声当作物品音效替代品 |

声音描述至少包含：**声源、材质、动作、触发时刻、音量、是否重复**。生产卡的 `at` 为动画进度 0～1，包含恰好 1 的结束触发。长按拿起和最终确认分开；移动每帧不重复播放。

本版内置可替换的原创合成拟音，支持金属、陶瓷、塑料、纸、布、木、液体、开关、脚步、低频震动；提供 WAV 文件供试听。也可在 `sound.src` 放入内嵌 WAV。录音必须可合法使用且不是空白，单条建议不超过 5 秒；其听感仍需人工确认。程序触发记录不能证明扬声器听感合格。

## 7. 生产卡接口与生成方式

顶层：`format: placement-plan-v1`、`id`、`style:{name,notes}`、`levels:[...]`。

每关：`id/title/kind/location/description/briefing/safety`、`objects`、`scene`、`targets`、`actions`、`risk`、`completion`、`review`；分阶段关卡另填 `flow` 与 `stageSounds`。完整可运行字段以随交付的 `策划案生产卡.json` 和源码 `example-plan.ts` 为例，不要把自然语言段落冒充这些字段。

```powershell
node scripts/placement-batch.mjs sample --output my-plan.json
node scripts/placement-batch.mjs check my-plan.json --output plan-report.json
node scripts/placement-batch.mjs build my-plan.json --output outputs/my-batch-001
```

以上命令在完整维护源码目录运行。输出目录须为空，防止旧关卡混入新批次。重复 ID 会阻止同名关导出；一关缺字段只阻止该关，其他合格关仍可生成。CLI 以非零退出码告知有被阻止的关卡。

图形界面：打开离线 HTML →“导入策划案 / 批量包”→选择 JSON →从顶部列表切换关卡→检查与试玩。编辑后的内容可以导出当前批量包，草稿使用 IndexedDB 保存，避免内嵌美术超出 localStorage 小配额。

## 8. 验收顺序

1. 核实逻辑与安全适用条件；人工批准的目标不得擅改。
2. 检查必填字段、唯一 ID、引用、目标可达、阶段可达、音效覆盖、坐标越界和目标重叠。
3. 浏览器真实拖拽：正确、错误、未命中、取消、前置条件、提前阶段操作、暂停、重置、通关。
4. 长按测试短按不成功、足时成功、松开/移开/暂停/失焦取消；限时未完成可以重练。
5. 看动作全过程，核对人物、物品、接触、遮挡、比例、风格和屏幕适配。
6. 检查音频能载入、每次触发对应事件；人工逐条听音。没有实测的真机、听音、视觉项保留 `not_run`。
