# 「怎么回事！」失败弹窗与小演出

用户确认了欠欠小红花预览后，本轮接入正式失败弹窗。深绿标题牌、金色手绘边框、米白纸面沿用开始/完成卡的视觉。

## 画面与文案

- 标题固定「怎么回事！」，旁边是独立的小红花监考员，眯眼、挑眉、抱臂。
- 找隐患：「漏了 N 处，还想领花？」；收纳：「还剩 N 件，这就收工了？」。N 来自实际运行状态，不解析字符串。
- 危险操作：「这操作，小红花都看愣了。」。具体原因仍用引擎原始反馈；不改写安全条件。
- 奖励说明「本局小红花：0 朵」在按钮上方。两个按钮竖排：「不服，再来！」与「返回地图」（独立关卡为「返回关卡」）；底部无附加文字。
- 标题、原因和按钮为真实 HTML 文本，图片没有烘焙文案。

## 动作节奏

1. 卡片 350ms 轻弹进入，标题立即可读。
2. 小红花延迟 140ms 歪头一次，650ms 内恢复；不循环晃动。
3. 吐槽延迟 220ms 出现，原因延迟 300ms 出现。
4. 「0」轻落一次；650ms 后金色按钮掠过一次柔和高光。
5. 按钮按下短暂压缩，移开/释放回弹。键盘有明确焦点样式。
6. 重试/返回后卡片 180ms 收起，才调用原 player 回调；240ms 定时器是动画被取消时的兜底。

两个按钮共用同步锁，屏蔽同一帧双击、过渡中的重复输入以及陈旧点击回调；卸载时清理待执行回调。失败阶段不走成绩保存；重试不靠自动开场 hook 再触发。

系统开启「减少动态效果」时，去除卡片、文字、小花与高光动画；退出立即执行，不等待过渡。运行中切换到该设置也会结束待执行的退出。

## 范围

只替换四种 player 已有的终止失败分支（共14个正式关卡）；不改变规则、奖励、倒计时长度、提前撤离或允许继续训练的零秒行为。不添加额外声音，复用现有交互声音流程。

最终 HTML、规则哈希与隔离静音浏览器验收结果另见本目录报告。真机与人耳：not_run。
