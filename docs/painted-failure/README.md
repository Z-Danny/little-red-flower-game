## 显示内容

- 待绽放的红花苞和两片叶子，米白纸面、深绿标题牌、金色边缘；没有奖励花阵列或成功绽放动画。
- 实际场景名称、鼓励短句、超时/危险操作提示、当前完成数量及重试建议。
- 找隐患、收纳分别从当前状态计算遗漏数量；危险操作直接使用原规则产生的原因。
- 主按钮“重新挑战”，次按钮在正式地图流程显示“返回地图”。零奖励说明放在按钮上方，按钮下方没有文字。
- 所有文字为 HTML；header/body/footer 为同一无字母版的连续切片，手势已换成花苞。两按钮位于正文流内，避免遮挡右下角花苞。
- 小屏按内容自然增长并可滚动，按钮触控区域至少 48px；标题获得初始焦点，按钮由 Base UI 模态约束焦点。

## 接入范围

只在已有 `phase === 'failed'` 时呈现，共 14 个正式关卡：9 个整场景找隐患关、2 个灾害专用关、2 个收纳关，以及火灾隔烟待援关的危险操作。

四个原 player 继续拥有失败判定、计时、操作、重试和返回回调。新 `PaintedFailure` 只负责显示，不触发成绩写入，不调整时间上限或判断条件。

- `scene-hunt/player.tsx`：超时显示未找到数量，重新挑战沿用原 `retry`。
- `disaster/player.tsx`：保留专用暴雨/洪水规则；洪水危险操作和超时保留其真实反馈。`evacuated` 仍为中性先行撤离。
- `configured/player.tsx`：收纳超时显示未收好数量；原重开回调不变。
- `configured/practice-player.tsx`：只接终止失败，继续尊重 `failureRevealing`。当前正式隔烟皮肤未开启该动画配置，不额外新增失败演出。
- 主动结束观察 `unfinished`、已先行撤离、普通可纠正错误和仍可继续训练的零秒状态不套失败弹窗。厨房没有 `failed`，本次不改变厨房规则。

## 验证

最终浏览器证据见 [验收报告](verification/README.md)。测试使用隔离档案、静音 headless 浏览器，所有 context 与 browser 在 finally 中关闭。加速的是浏览器 RAF/timer，首次失败使用实际引擎及指针输入；重试后的部分重复超时使用单独标注的受控时钟边界。原始用户存档不会被测试打开。

14 个失败入口、56 个布局样本，以及失败后重试再成功的真实输入闭环均通过。长跑期间另一任务数次重新导出了音乐版本，导致整份 HTML 的前后哈希一致性断言失败；此项和功能通过分别记录。随后对最新 `2b4ca25f…e89fa` 导出做了 [三入口复核](latest-artifact-smoke/README.md)：3 个入口、6 个布局、两按钮行为通过，文件前后哈希稳定。

另一个开场流程任务随后在两个 player 中新增了自动开始和加载重试逻辑；本任务保留这些并行改动，不宣称尚未导出的开场流程已经过本轮浏览器验证。失败组件、失败样式和失败渲染块保持本轮版本。

单元检查与厨房美术校验通过。第一次整套验证遇到并行音乐任务尚未落盘的引用文件；文件到位后重新执行类型检查和生产构建通过，本任务未修改音乐代码。最终 HTML 单独导出并验证。
