# 台风前的家 · 二维分层重制

## 本次实现与最新反馈

第一关完整可玩；其他五关仍锁定，不冒充已完成。背景固定，物件、人物和天气分别绘制。所有目标剪影直接使用对应物件 PNG 的 alpha 轮廓，不使用场景裁块。

按用户后续反馈：删除遮挡花盆的雨伞；晾衣杆改为向室内（画面下方）移动并淡出；墙上固定插座。插头初始覆盖插孔且金属脚藏入插座，拔出时逐步露出。插线板状态灯按本关约定由接通绿变为断开红，再收到沙发侧边；坐垫移开后淡出收起，不留在座面。电线两端随插头和插线板移动，避免断开和通关坐姿踩到它。

| 动作 | 时长 | 持久结果 |
| --- | --- | --- |
| 花盆 | 1100 ms | 同一花盆移到室内地面 |
| 窗户 | 1200 ms | 窗扇关闭、窗扣转动，室内飘雨停止 |
| 晾衣杆 | 1000 ms | 向内收回后消失，表示收妥 |
| 沙发垫（前置） | 750 ms | 向上拿开并淡出收起，插线板露出，不计入五个目标 |
| 插线板 | 1250 ms | 拔插头、状态灯从绿变红，再将插线板及电线收到侧边 |
| 柜门 | 1100 ms | 绕铰链合拢，固定带扣紧 |

风险缓慢上涨；36、62、82 阶段分别提示花盆、进雨、柜门；100 时播放强风反馈但不终止关卡。误点无惩罚，重复点击与处理中的点击不会重复得分。完成后风险停止，展示 2.8 秒安全场景，再发放小红花。切后台暂停游戏计时。

## 模块边界

- `app/game/typhoon/config.ts`：唯一的美术路径、720×960 设计坐标、目标时长、前置关系、风险阈值与文案配置。
- `app/game/typhoon/model.ts`：纯 reducer。事件为 start / tick / hit / hint / miss / reset；不依赖浏览器和图片，不调用声音或绘制 API。
- `app/game/typhoon/animation.ts`：纯函数将玩法状态转成物件位置、旋转、透明度和层级。修改动作不会改变奖励判定。
- `components/game/typhoon/asset-loader.ts`：加载素材并读取 alpha，用同一份素材同时支持画面和点击判定。
- `components/game/typhoon/canvas-renderer.ts`：绘制固定背景、独立物件、风雨和轻提示。反向变换后读取 alpha，避免透明空白处也算点击目标；窗扇内可见玻璃区域另设合理命中判定。
- `components/game/typhoon/scene-canvas.tsx`：响应式画布、鼠标/触摸输入及键盘操作入口。
- `components/game/typhoon/typhoon-player.tsx`：顶部目标、界面、短音效、通关回调。每次通关只调用一次奖励回调。
- `app/game/levels.ts`：共享关卡目录，从本关配置生成兼容元数据，不再维护第二套台风动作数值。

旧的其他关卡模块保留；第一关不再调用 `find-hazard-feedback.tsx` 的场景补丁实现。未改动用户已有的独立 `h5/` 项目。

## 修改工作流

1. 修改素材：替换 `public/levels/typhoon-v2/` 对应 PNG，必须保留真实 alpha；不要把棋盘格印在图里。
2. 修改布局：调整 config 的 placement。使用左上原点的 720×960 坐标，视口缩放由画布处理。
3. 修改时长：改 actions.duration；动画进度和完成判定共享这个值。保持 500～1500 ms。
4. 修改动作：改 animation 的 sceneSprites；renderer 与 alpha 命中判定自动复用同一变换。
5. 修改知识或提示：改 config 的 summary / hint / during / done。公开上线前需专业科普审校。
6. 验证：`node scripts/test-typhoon.mjs`，`node scripts/review-typhoon-art.mjs`，`pnpm build`。
7. 导出：`pnpm export:offline`。产物包含脚本、样式和图片，不依赖服务器或 CDN。
