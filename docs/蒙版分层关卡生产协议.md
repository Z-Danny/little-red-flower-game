# 蒙版分层关卡生产协议

版本 1.0 · 2026-09-07 · 状态：试制规范，不是已经运行成功的批量流水线。

## 1. 目标与本轮边界

采用用户提出的“先画完整场景，再拆可交互物件”路线，减少背景与单独生成的物件在透视、光照、纹理上的不一致。复杂物件依然允许每种状态一张透明图；位移、旋转、缩放、淡出交给程序。

本轮已实现的是厨房沉浸式 UI、竖屏场景与旧透明物件的装配。没有执行蒙版批量生成、程序抠图和补空试验，不能引用这份规范声称蒙版法已稳定。本文件是下一关开始生产时的试制协议。不要为改 UI 擅自重画所有已认可的人物状态。

## 2. 先锁画面，再拆图

1. 定义唯一 master 尺寸、相机、完整场景对象清单、物品 ID、静态遮挡物、可交互安全区域。
2. 生成带可交互物品的完整母图 `master.png`。主图没有 HUD、答案步骤和文字名牌。先检查手机可读性、支撑面、手脚、尺度、透视、灯光。
3. 母图通过后计算 SHA-256 并冻结。任何后续蒙版、补空和状态图都引用同一版本；母图修改后，原蒙版和坐标一律作废，不能混用。
4. 为每个可交互物件生成或人工校正独立的像素蒙版，保持母图的完整画布尺寸。白为物体、黑为背景，灰度只允许出现在需要柔化的边界。彩色实例 ID 图可用于分配物件，但不能把彩色标签当最终软 alpha。
5. 用经校验的蒙版从母图提取物件，保留原始 RGB 与轮廓，不重新生成一张“相似物品”代替抠图。
6. 汇总所有可移动物件及应移除的接触阴影，生成补空区域。在母图上只补这一区域，得到 `clean-plate.png`。
7. 把提取物件按原始位置放回补空背景，做回贴对比。母图能被重建后，再生成物件状态变体和动作。

## 3. 必需产物契约

```text
production/<job>/mask-attempt-001/
  master.png                  冻结的完整母图
  master.sha256               唯一基准哈希
  objects.json                尺寸、物件 ID、层级、锚点、状态清单
  masks/<id>.png              与 master 同宽高的灰度蒙版
  sprites/<id>-initial.png    真正 RGBA，提取后的初始物件
  sprites/<id>-<state>.png    同坐标基准的状态变体
  clean-plate-candidate.png   生图补空候选结果，不能直接发布
  clean-plate.png             校正并通过验收的干净背景
  review/reassembled.png     初始状态回贴合成
  review/diff.png             与母图的差异可视化
  review/edges-light.png     透明物件在浅色底的边缘检查
  review/edges-dark.png      深色底检查
  report.json                 检查项、结果、实际证据、失败原因
```

`objects.json` 最少包含：`masterHash / canvasWidth / canvasHeight / objectId / maskPath / crop{x,y,w,h} / pivot{x,y} / depth / parentId / states / occludes / shadowPolicy`。锚点统一使用母图像素或明确标注的局部像素，禁止混用百分比和像素。

裁图必须自动保存裁切偏移 `crop.x/y`，边界留 2–4 px 透明安全区。不能机械九等分图集，也不能各状态单独紧裁后拉成一样大。运行布局从母图坐标换算；不能先拍脑袋配位置，再强扭物件去迁就。

## 4. 蒙版与去背门禁

- 尺寸必须与冻结母图一致，禁止为了通过校验把错位蒙版强行拉伸。
- 不接受“有一圈白边”的粗框或画出来的棋盘格。蒙版不能含物件名、数字、颜色图例或水印。
- 同一物件不应漏掉把手、细杆、线缆；杯把等孔洞必须透出背景。物体未被遮挡的外轮廓要连续。
- 物件之间的蒙版不得无意重叠。被遮挡部分需要单独记录，不能把遮挡物一起抠走。
- AI 重新画出的蒙版可能有几何漂移，必须将轮廓叠在原母图上检查。未达标则人工/确定性工具修边；最多两次生成重试，仍失败停止这一物件，不重复整关烧图。
- 灰度边缘只是 alpha 候选。母图边缘颜色已经混合背景，直接乘 alpha 会出现白边或暗边；需要依据原背景做颜色去污染，并在浅/深底都检查。半透明玻璃、烟雾、反光和发丝单列难例，不宣称一个阈值能全部解决。
- 阴影按 `shadowPolicy` 拆分：跟随物件的接触阴影可独立层绘制；原位地面阴影必须随补空移除，否则物件移动后会留“幽灵”。

## 5. 补空与遮挡门禁

补空生成可能改变蒙版之外的图像，提示词承诺不等于像素不变。必须将候选补空与母图逐像素比较；最终背景只接受扩张/羽化后的补空区域，区域外使用原母图像素。若工具不能精确使用输入蒙版，不伪称支持，可将蒙版作参考生成候选，再经用户允许的本地合成完成区域约束。

遮挡分两类：

- 普通静态遮挡：从母图提取遮挡物为前景层，例如柜沿挡住锅底；前景层放在物件上方，不能把柜沿画进锅的 PNG。
- 隐藏目标：需要先移开前置物品，例如沙发垫下插线板。被遮挡部分原母图没有像素，无法“抠出完整物件”，必须补画完整物件再由上层遮住。默认蒙版只表示可见像素，不冒充完整几何。

移动前后的区域必须都有可用背景。把一块矩形修补图贴在原场景上不是分层验收通过。

## 6. 状态与交互契约

初始、处理中、处理后等状态共用画布和 pivot。若只是移动、转动、收回，复用同一 RGBA 加程序动画；若轮廓真的变化才生状态图，例如开门/关门、惊慌/平静。

动画参数、资源映射、输入判定分别独立配置。相机变化必须同时用于绘制和反向命中。可点击区域对应实际可见轮廓，不给空白区域藏按钮。处理动画结束时才提交安全状态；处理中拒绝重复操作。物品在初始位置、拖拽层和处理层三者互斥，不保留副本。

## 7. 沉浸式 UI 契约

- 游戏区优先使用全部可用竖屏高度；画面等比例缩放，不拉伸人物、不裁掉可操作物件。极端尺寸优先完整可操作，不以“全屏”为由丢失目标。
- 常驻只留关卡编号/短标题、计时或风险、返回和暂停。默认不显示正确动作清单、三步答案、人物头像说明卡、工具栏和长说明。
- 正确动作由动画与状态图传达，不显示“正在盖锅盖”等字幕。没有必要的成功反馈也不强加一条。
- 错误原因最多一个短提示，约 2 秒后消失；火势与表情同时反馈。不能上下一条、场景一条重复播报。
- 新手提示由玩家主动打开；菜单、提示、键盘辅助不是常驻大面板。
- 暂停菜单真正暂停风险和动画；重玩恢复物件状态但不清空历史最佳奖励。
- 结算只在完成后出现，用一个简短知识总结和奖励收尾。

## 8. 首次试制与批量门槛

先选择一关的 3–6 个目标试制，不直接批量十关。记录每个目标的修边耗时、补空重试次数、回贴误差和手机可识别性。两关连续通过下面检查，再考虑提取通用脚本；不要复制一关硬编码成“批量工具”。

1. 物品静止回贴与母图相比没有明显位移、阴影漂移或风格跳变；保存原尺寸 diff，不只看缩略图。
2. 全部物品移开后没有残影、洞、重复物件、错接桌沿和不连续纹理。
3. 深浅底、真实背景、移动中间帧都没有白边和矩形底；透明边缘输入可穿透。
4. 所有物件都能在 320、390、430 px 宽屏幕找到并完成操作；截图不能代替实际拖动。
5. 正确/错误/无关操作、前置解锁、风险到顶、暂停、重玩和结算都执行通过。
6. 单文件导出含所有资源；源文件、提示词、蒙版、版本和测试证据保存在项目内，临时目录不能成为运行依赖。

任何门禁失败，报告明确 FAIL/NOT_RUN 与下一步。文档、命令存在、JSON 能解析都不算流水线已经稳定运行。
