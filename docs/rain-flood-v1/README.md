# 暴雨与洪水新增关：复用工作流

版本：2026-09-10。先读 [设计与安全复核](设计与安全复核.md)，原始输入完整保存在 `inputs/`。本文件说明实际采用的流水线，不承诺 AI 原图一次生成即可直接发布。

## 模块边界

|位置|职责|改画风时是否需要修改|
|---|---|---|
|`content/disaster/<id>/rules.json`|目标、先后条件、计时、动画种类、反馈、总结|不改机制则不修改|
|同目录 `skin.json`|原图、结束图、切片、原像素蒙版、落点、姿态|需要，由编译器生成|
|`app/game/disaster/model.ts`|纯状态机、重复事件幂等、失败与计分|通常不需要|
|`app/game/disaster/scene.ts`|根据状态计算物体姿态，统一相机变换|通常不需要|
|`components/game/disaster/`|加载、绘制、透明像素命中、拖放、界面、音频生命周期|通常不需要|
|`art-source/rain-flood-v1/<street或flood>/`|原画、同构 ID 蒙版、补空候选、结局、制作配置|换皮时新建版本，不覆盖已发布素材|
|`public/levels/rain-flood-v1/`|真正可离线使用的 WebP、透明 PNG、运行时 ID 图、溯源报告|编译生成|
|`scripts/prepare-rain-flood.py`|蒙版规范化、原像素切片、剪影、受限羽化补空、命中样本|复用工具，按制作配置编译|

`app/game/disaster/registry.ts` 注册这两个包；`app/game/levels.ts` 提供地图、预览和排行榜元数据；`game-app.tsx` 路由到独立播放器。旧 `scene-hunt` 和 `configured-v1` 的规则保持不变。当前新增适配器服务这两个七项训练关；加入不同数量/策略的关卡前，先扩展契约与测试，不可绕过校验硬塞配置。

## 美术流水线

1. **审核设计**：逐条核对现实安全条件，写清哪些是圈选、模拟求救或安全方案示意。先确定唯一 ID 和玩法，再作图。
2. **完整母图**：内置 imagegen 生成一张含人物、物品和隐患的 9:16 完整绘本场景。风格提示词按 `illustration-art-style` 模板整理。使用的是工具默认模型，不能指定或核实具体 GPT Image 版本。
3. **同构蒙版**：引用母图生成等尺寸、同机位的纯色 ID 图。每个颜色只代表一个目标；不能把新绘制的另一间屋子当成蒙版。本轮暴雨 7 色、洪水 10 色。检查目标边缘与原图叠合，不只检查像素数量。
4. **补空与结局**：洪水关移除可操作物件生成干净底图；结局保持同机位，把人物转移至高处，不凭空让室外洪水消失。暴雨结局表现另一时点由相关人员完成的防范措施，不鼓励玩家在暴雨中移车、触线或放路障。
5. **像素编译**：`production.json` 保存调色板、名称、实际位置限制和姿态。程序采用最近调色板分类，剔除孤立噪点，按核准多边形限制断线/招牌/电闸区域；剪影和物品颜色都来自母图，不另画一套物件。
6. **不动就保留原画**：初始画面直接显示完整原画。只有移动、收纳或进入演出状态的物品才显示局部补空与透明切片。补空边缘羽化，其他物体的 ID 区域受到保护，不以矩形图片覆盖邻居。
7. **视觉退回条件**：假透明棋盘格、白边、细长目标不可点击、人物踩在物资上、退路被堵、雨落在室内人物脸上、初始与结局机位明显漂移。发现任何一项先修素材或坐标，再接入验证。

完整生成提示词分别在 `prompts.json`、`derivative-prompts.json`、`ending-expression-prompts.json`。实际生成 PNG 保存在 art-source，绝不依赖临时生图目录。`provenance.json` 留存源文件 SHA256。

## 本轮具体修正记录

- 新文档要求七项目标和失败，旧关却是五目标且允许继续：新增独立 `disaster-v1`，没有改变旧版契约。
- 电闸蒙版候选存在远处粉色杂点：按真实墙上盒体核准区域截断，并采用最近调色板分类，避免错误颜色串入。
- 街道招牌挂架跨到 HUD、断线顶部贴近手机裁切边：目标区域锁在实际招牌与低垂断头，命中样本落在手机安全可见范围，不改图片比例。
- 直接补空造成椅脚浅边：未操作物品留在母图，只在移动位置按透明蒙版羽化补空，保护邻近物体像素。
- 第一版人物楼梯姿态与背包重叠：把落脚点移至背包上方的实际楼梯，增加“脚不落在背包上”的自动断言。
- 灾害源效果只叠在室外多边形；水位、雨量、暗部和音乐随风险变化。没有人声合成或网络音频依赖。
- 旧厨房目录测试将未知引擎当作旧手写关：新增引擎注册后更新其分类排除项；厨房动作、贴图、层级和判定未修改。

## 编译与验证

在完整项目目录中运行：

```powershell
python scripts/prepare-rain-flood.py street
python scripts/prepare-rain-flood.py flood
pnpm test:disaster
pnpm test
pnpm typecheck
pnpm build
pnpm export:offline
pnpm test:disaster-browser
```

素材编译需要 Pillow、NumPy、SciPy；无网络调用。`skin.json` 是编译产物，调整位置请改 `production.json` 后重编，不要直接修改生成文件再被覆盖。

浏览器验收脚本在本机安装的 Edge 中使用独立、静音、无个人存档的测试上下文，`finally` 关闭测试浏览器。脚本中的浏览器与 Playwright 路径是当前开发机配置，其他开发者可替换为自己的已安装运行环境。单文件游戏本身没有这些开发依赖。

测试报告在 `outputs/rain-flood-v1/`；发布时保存验收摘要到本目录 `verification/`。使用的离线文件哈希必须与报告一致。纯规则测试不是视觉验收，截图验收也不代替实体手机触控或真实扬声器听感。
