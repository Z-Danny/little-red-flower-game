# 暖色纸纹绘本皮肤 v1

两关共使用 30 张新生成的运行素材：2 张背景、28 张透明道具与人物。使用内置 imagegen 逐张重绘；未指定或宣称具体模型版本。32 次生成包含厨房构图返工和刀具去背返工，淘汰版本也保留在本地原稿中。

## 当前接入方式

- `content/presets/kitchen/skin.json`：厨房资源、物件位置、目标区域与镜头安全范围。
- `content/presets/typhoon/skin.json`：客厅资源、物件位置、插头/电线连接锚点与红绿状态灯。
- `public/levels/paperbook-kitchen-v1/`：厨房背景、9 种物件/特效和 4 种人物表情。
- `public/levels/paperbook-typhoon-v1/`：客厅背景、独立目标、连接件和站立/坐下的母子。
- 旧 `kitchen-v1`、`typhoon-v2` 素材不删除。引擎编号仍是旧编号，它代表机制版本，不代表美术版本。

规则状态机、正确/错误交互、风险系统、动画时长和结算条件没有改动。顶部剪影继续直接引用对应物件的同一张 PNG。雨伞素材保留用于后续组合，但原关卡仍不绘制已移除的悬空雨伞。

## 厨房新构图的摆放约束

正对灶台和正面橱柜，右侧是通向走廊的出口，不再使用斜向 L 形台面。锅放在左侧灶眼；旋钮位于炉具前面；抹布放右侧台面；锅盖、水杯、盘子和刀具放前方备餐桌；灭火器位于右侧通道边；人物站在灶台旁，撤离后落脚于门外走廊。

不要只换背景而不重新校准皮肤配置。锅盖必须覆盖锅口；火焰根部要在锅内；灭火器不能超出窄屏可见范围；人物脚底不能落在桌面或餐具上。场景中的门只是图片，实际出口判定来自 `layout.zones.exit`。

## 原稿与可复现加工

`art-source/paperbook-v1/generation-log.json` 保存每次最终使用的中文提示词、原稿路径、替换目标及淘汰标记。`raw/` 保留全部生成原稿；`style-reference.png` 是用户提供的风格参考，不是游戏运行资源。

生成工具的部分原稿没有真实透明通道，画入了棋盘格或纯色底。经用户允许使用本地程序去背、边缘净化与尺寸对齐。绝不能把原稿直接复制成运行素材。

```powershell
# 仅重建本皮肤；Python 需要 Pillow、numpy、scipy。
python scripts/prepare-paperbook-art.py
node scripts/paperbook-contact.mjs
node scripts/check-paperbook-art.mjs
node scripts/check-kitchen-art.mjs
node scripts/review-typhoon-art.mjs
```

加工器仅读取本地原稿和历史素材的透明边界，输出到新皮肤目录。它保留旧画布大小及可见边界，避免角色表情切换造成位置漂移。刀具的最终原稿为纯洋红底版本，避免灰色刀刃被棋盘格算法误删。源文件中的绝对生成路径仅用于追溯，不是运行依赖；重建使用已保存的 `raw/`。

## 验收与导出

```powershell
node scripts/levels.mjs validate
pnpm test
pnpm typecheck
pnpm build
pnpm export:offline
```

自动检查不能替代视觉验收。还需在手机尺寸下检查：初始/处理中/安全三个状态、透明边缘、人物脚底、插头与电线连接、绿色接通与红色断开、坐垫和晾衣杆收起消失、锅盖遮盖、错误泼水时火焰扩大、旋钮点击旋转、出口拖放，以及风险到顶仍可通关。

离线入口是 `outputs/本地离线版/小红花应急行动.html`，图片、样式和脚本均内嵌，不依赖 localhost 或外网。修改素材后必须重新导出；只修改 PNG 不会自动改变旧的单文件 HTML。

## 后续换风格

继续使用同一套 asset key，不改规则 ID 和机制实现。新风格用新的目录与皮肤配置，按当前参考图统一重画人物、背景和所有交互物件。若改了构图，仅校准 skin 中的几何与视觉锚点，不把位置写进状态机。商业发布前仍需核对商标、参考素材来源以及整套作品的使用授权；生成和技术验收不等同于法律保证。
