# 音效补齐与响度校准

## 响度调整（2026-09-15）

- 校准按钮、提示、种花、圈选／收集、正确／错误、成功／失败，以及练习和厨房动作声。按短音实际活动段能量匹配，保留轻反馈、动作、收尾的层次。
- 原来明显偏小的音效提高；厨房原本较响的锅盖、成功等保留原有量级，补强燃气、布料等弱音。用户选定的地图 BGM、关卡音乐／环境及已禁用的人物音策略保留。
- 找隐患／灾害／收集的反馈使用独立总线，避免原来针对环境的压缩器把短提示压得过轻；混合出口统一限制采样峰值。练习、厨房和 UI 同样加入末端限峰，音量滑杆、静音仍有效。
- 按钮点击从 45ms 延长至 90ms。返回地图时允许最后一次按钮音播完，最多 450ms 后关闭旧 UI 音频会话；隐藏页面仍立即停止。
- 修复收集关进入 complete 后成功音被 inactive 状态拦住的问题；成功声播放完自动静音。暂停、静音、隐藏时停止当前反馈，恢复时不补播旧尾声。
- 仍缺的动作音色与接线，见 [当前 24 关声音缺口清单](missing-sounds-audit.md)。本轮没有把泛提示音描述成已制作好的电话、布料或脚步拟音。

原生浏览器波形测量入口：`node scripts/measure-sfx-levels.mjs` 和 `node scripts/measure-ui-hunt-sfx.mjs`。指标为活动段 RMS 和采样峰值，**不是 LUFS、扬声器声压或人耳听感验收**。最新数值与最终 HTML 检验见 `loudness-verification.json`。

## 范围

|位置|本轮声音|触发方式|
|---|---|---|
|电梯故障待援 `lift-wait`|138 BPM 短节奏、轿厢底声、通话、拿起、等待、危险退回、完成|原有动作和完成状态|
|井口遇险求助 `well-call`|138 BPM 短节奏、室外底声、两种通话、后退、拿起、危险退回、完成|原有动作和完成状态|
|汛期应急包、楼道杂物清理|拿起、无效放回|有效拿起及新的一次无效动作|
|首页、地图及各类关卡按钮|短促点击和双音提示|button click，同一触摸/鼠标/键盘操作一次|
|返回地图种花|落地、冒芽、开花、计数、真正的新关解锁|现有种花动画时间线|

用户选定的③《忙归忙，能搞定》仍用于首页和地图。两个旧处置关使用原创程序合成的简短节奏与现有非语言音效引擎；没有生成或加入任何朗读、歌词、角色台词。电梯与井口仍是训练用时，不增加灾害倒数或虚构救援抵达时间。

## 控制和实现

- 地图设置里的“按钮／奖励音效”控制首页、地图和种花，设置在本机记忆；首页／地图音乐保持独立开关。
- 关卡按钮音跟随本关静音以及交互音效音量。独立短音引擎允许暂停按钮播完反馈，同时场景背景声音暂停。
- 通用 click 排除关卡键盘物件操作区、音量控制和不可用按钮，不叠加已有动作音；不为移动、滚动、悬停播放声音。
- `RewardSound` 在用户操作后创建 AudioContext；所有短音节点跟踪并断开，静音、后台与销毁取消已排程音符，过期异步点击不补播。
- `PlantingAudioTracker` 跟随现有动画 age；按 nonce 去重，静音时仍消费时间点，重玩或没有真正解锁新关时不播解锁音。领奖保存时原有和弦已移至种花时间线。
- 两个旧处置关通过独立音频配置适配 `PracticeAudioSession`，不改变游戏渲染器、规则、皮肤、ID 或成绩。

## 验证

定向测试加入 `pnpm test`；最终 HTML 浏览器验收入口：

```sh
pnpm test:audio-feedback-browser
pnpm test:journey-music-browser
```

测试使用隔离的离线浏览器、`--mute-audio` 和 finally 关闭；预置存档仅用于打开测试关卡，电梯/井口完成由真实键盘事件触发。最终状态和文件指纹见 `verification.json`。

人耳试听与实体手机验收：**not_run**。自动测试验证触发、声音采样与资源生命周期，不等同于主观听感验收。
