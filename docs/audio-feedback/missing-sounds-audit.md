- 上一轮已补的电梯／井口旧关、收集关拾起与回弹、各关提示和按钮、地图种花五阶段，当前都有声音路径，不能再列成整关无声。

- 八个练习关的动作都有声音兜底。主要问题是一些配置名字像拟音，实际却生成普通音符，例如 `fabric`、`switch`、`stairs`。
- 当前两灾害关**没有沙袋或关门窗动作**。暴雨关是七目标圈选；洪水关是上楼、断电、求救、收物资、整理漂浮材料。旧的“沙袋／门窗缺声”不适用于当前版本。
- **本轮已完成：导航按钮短音被卸载截断。** UI 会话现在用 `retire()` 播完已接受的短音再释放；后台／静音等仍立即取消。此项不再计入待补声音。
- **本轮已完成：收集关成功声被 inactive 状态挡住。** 成功结尾现在调用独立 `finish()` 短窗口；关卡音乐仍在结束时停止。
- **本轮已完成：UI／找隐患反馈响度统一。** 原生 OfflineAudioContext 实测 UI active RMS 为 0.080–0.095；找隐患起笔 0.085、发现／错误 0.110、结尾 0.125。单音与压力叠加峰值均不超过 0.7。这是数字音频输出标定，人耳可听性仍需试听；具体报告见 `outputs/audio-loudness-work/ui-hunt-measurements/report.json`。

### 八练习中“命名像拟音、实际是普通音符”的具体原因

`app/game/runtime/practice-audio.ts::cueRecipe` 用 ID 里的英文片段选择合成方法：

- `fabric` 没命中 `cloth|gauze|glove|shoe|rustle|seal`，变成 `tone`。
- `stairs` 没命中 `step|walk|position`，变成 `tone`。
- `switch`、`rumble`、`ground-settle`、`outside-air`、`bottle-place` 也会变成 `tone`。
- `radio-static` 命中 `radio`，结果是两段音高变化的 signal，而不是静电声。
- `window-motor` 虽命中 mechanical，但其实现仍是约 0.3 秒的噪声瞬态加衰减音符，不是完整车窗马达过程。
- `telephone-connect`、`fire-alarm`、`heartbeat`、`nonverbal-cough`、`rescue-arrival`、`exit-door-latch` 由 `emergencySound` 提供专属 PCM；洪水三种动作和双层环境由 `floodSound`／`synthesiseFloodLoop` 提供，不属于上述兜底音符。

建议先对这些明确动作建立显式映射，避免只加大音量后“所有动作都是更响的叮”。

## 四、明确不列入待补清单

- 油锅起火处置的 `characterEnabled:false` 保持；不恢复惊叫、喘息、语音或归在人物总线的撤离脚步。
- 台风居家准备的 `characterAudio:none` 保持。
- 不添加 TTS、人物台词或播报规则。
- 不为油锅关、旧电梯／井口等未配置倒计时失败的情境新造“超时失败”声音。
- 不把风雨圈选、车辆正常降窗等玩法改成实际处置／破窗事件。
- 静音／音量为零本身不是漏接。地图按钮／奖励静音会保存到 `red-flower:interface-muted`；首页没有直接状态提示，地图齿轮“游戏设置”里可恢复；关内又有独立静音。这是可发现性和设置范围问题，建议设置名称明确范围，并在总响度验收前检查实际存储状态。
- 已排除 `.hunt-keyboard`、`.configured-keyboard`、`.disaster-keyboard` 等场景操作，不再普遍叠加 UI click。父级 GameApp 在进行中的关卡禁用自己的 capture，普通关内操作不会触发双份 UI 声。
