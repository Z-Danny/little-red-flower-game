# 统一挑战HUD与50秒节奏（现行）

版本：2026-09-13。此文替代历史“90秒正计时”“常驻剪影”“台风专属50秒”和“超时仍继续找”的生产要求。历史测试夹具保留兼容测试，不可复制成生产模板。

2026-09-15 视觉更新：见 [手绘关卡 UI](../painted-ui/README.md)。按用户要求，进度条改为最顶部的金色手绘轨道和红花花瓣指针，下方为返回、标题、提示、暂停；居中弹窗使用各关场景文案。该更新替代本文旧的行序与基础配色，时间、提示交互及终局规则继续有效。

## 范围与不可变项

- 9个整场景找隐患：台风、充电卧室及七个v2关，仍是识别、描红圈、完整结果图。
- 暴雨前的街道：仍是7目标识别；误点扣5秒保留，扣时同步缩短彩条；奖励阈值随总时长同比缩放。
- 汛期应急包、畅通的生命通道：仍是点击收纳和原来的独立物件动画，不改成描圈。
- 不改变任何背景、人物原画、目标蒙版、世界坐标、相机和手机适配，不改变处置关机制。

## 唯一显示合同

1. HUD第一行是返回、关卡标题、灯泡、暂停。灯泡位于暂停左边，按钮至少44×44 CSS像素。
2. 第二行仅一条横向填满HUD可用宽度的彩条。禁止可见秒数、秒数字徽章、重复计时行。仅保留读屏用的ARIA剩余值和状态说明。
3. 剪影默认隐藏，必须用hidden/display:none移除遮挡和点击区域。鼠标悬停临时展开，离开220ms收起；点击固定展开，再点收起；触屏点击切换，不能要求手机具备hover。
4. 键盘聚焦可展开，Escape收起；点击场景、暂停、切后台、阶段切换、完成一个目标、重试时收起。打开灯泡不会停表或更改相机。
5. 剪影在顶部横排，数量来自规则；不能增加左侧栏或给图像额外留出顶部空白。
6. 不在该HUD中发明视口逻辑。场景比例、等比缩放与世界到屏幕的变换继续由各引擎已有共享视口负责。

## 时间和终局合同

- 2026-09-13更新：上述12关每次有效误点扣5秒，彩条立即缩短并出现“−5秒”反馈；连续误点逐次扣时，不用反馈冷却免除扣时。只扣时间，不再额外扣花朵。剩余不足5秒直接失败并归零。
- 正确目标、仍可见的已完成物件、进入前/暂停/结算、提示和导航按钮不触发误点扣时。整场景找隐患在非最后一个目标的描圈期间，误点也扣5秒，正确输入不排队；最后目标已接受则保护既有完成动画。收纳处理期间仍锁定输入。已经移走的物件原位置是空场景，重新点击按误点处理。
- 共用规则入口：`app/game/challenge/rules.ts`。整场景及配置收纳引擎仅在`timeout: fail`的找隐患挑战启用；街道引擎保持规则文件`missPenalty: 5`，测试约束三入口一致。新模板采用同一挑战引擎即可继承，不允许皮肤自行计时。

- 玩家点击“进入场景”才启动50秒并解锁音频；加载或等待开始不消耗时间。
- 0–25秒绿色、25–40秒琥珀色、40–50秒红色；长度从100%逐渐缩到0。规则时钟是唯一依据，不能另外用CSS倒计时。
- 暂停或网页进入后台：时钟冻结、声音停止；恢复不补扣隐藏时长。
- 50秒仍未完成则failed，禁止晚到输入，不显示成功图、不奖励、不覆盖既有最佳成绩。
- 最后一个正确输入必须早于截止；截止前点中的最后目标允许其已有处理动画完成，不额外扣掉强制动画时长。50.000秒新输入无效。
- 失败按钮“重新挑战”直接开启新一局，清空目标、提示、动画、声音队列与计时；不清除本地存档。
- 文案应明确这是游戏限时训练，不暗示现实应急必须按50秒行动或等待倒计时结束。

## 解耦接口

|层|位置|修改边界|
|---|---|---|
|通用条|components/game/scene-hunt/countdown-bar.tsx|只消费elapsed/seconds/resolved；无玩法判定、无关卡ID|
|灯泡与交互|hint-toggle.tsx、use-hint-disclosure.ts|三引擎共用；只管理展开状态|
|整场景规则|content/scenes/<id>/rules.json|seconds:50、timeout:"fail"；目标和知识不变|
|整场景外观|presentation.json|timer:"pressure-bar"、clues:"on-demand"；不把图片路径写进规则|
|阶段演出|performance.json|timing:"quarters"；四档按0%、25%、50%、75%活动进度选择|
|街道规则|content/disaster/rain-street-preparation-v1/rules.json|seconds:50；保留七目标、误点罚时和原引擎|
|收纳规则|content/levels/<id>/level.json|risk.seconds:50、risk.timeout:"fail"；risk.mode:"elapsed"不凭空制造室内灾害|
|收纳声音适配|use-collection-sound.ts|复用HuntSound的室内音乐和反馈；不改收纳机制|
|共用样式|app/scene-hunt.css、app/challenge-hud.css|后者仅处理不同引擎的HUD接入，不覆盖相机|

performance.stages.atMs保留0/30000/60000/90000的历史编排参考以兼容旧测试；启用timing:"quarters"后实际四阶段是0/12.5/25/37.5秒。渲染和音频必须调用携带rules.seconds的performanceStage/performanceTier，不能直接拿atMs做当前关卡计时。

## 声音

音乐、环境音和动态共用活动时间比例。每关维持原场景的声音类别：室内收纳不加风雨/燃烧。台风关按最新要求设置 characterAudio:"none"，不再播放8/27/43秒人物惊叫；背景音乐、风雨及交互音效保留。不使用AI朗读，尚未生成新的呼吸音。旧惊叫素材的授权记录仅为历史凭据，不是当前启用要求。

共用HuntSound有独立音乐、环境、交互、人物通道；失败使用短结束音，短尾结束后静音；暂停、隐藏、退出停止并释放。音频只能通过玩家点击解锁。不以浏览器RMS替代人耳音色评价。

## AI接入步骤与提示词

先完整阅读../hunt-pipeline/AI_START.md及README.md。新整场景关通过scripts/hunts.mjs create/batch生成；现行content/hunt-template/template.json已经包含上述规则和表现默认值。不要复制旧关组件、旧90秒配置或测试夹具。

可复制给实现AI：

> 在最新完整源码中接入本关，规则、皮肤、文案、演出、视口保持独立。复用现行CountdownBar、HintToggle、useHintDisclosure及对应引擎，不复制组件。50秒，从用户进入开始；仅显示铺满HUD宽度的递减彩条，不显示具体秒数。暂停左侧灯泡默认收起剪影，鼠标hover/click和触屏click展开顶部横排；关闭后无布局占位和点击遮挡。所有动态与声音使用同一活动时间比例。50秒未完成失败重试，保留截止前最后一次有效输入的既定动画。保持原图、蒙版、命中坐标和已有手机/桌面视口，禁止拉伸、留黑边或另建适配。验证暂停、后台、重试、不重复奖励、无外网离线运行；如未真机/未试听，明确标记not_run。
