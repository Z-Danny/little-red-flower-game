# 《厨房着火了》分层处置关卡 · 交付与维护说明

版本：2026-09-05。入口是当前 React/Vinext 主游戏，不是独立 `h5/` Phaser 示例。旧台风关与 `h5/` 均保留。本文件记录已实现的第二关，不宣称所有关卡均可零代码生成。

## 1. 启动与交付

```powershell
pnpm dev
# 浏览器打开 http://localhost:3000/
node scripts/test-kitchen.mjs
node scripts/test-typhoon.mjs
pnpm exec tsc --noEmit
pnpm build
pnpm export:offline
```

地图中可选择两关，有实际分层场景预览。厨房默认为本次新增关卡预览。

离线文件位于 `outputs/本地离线版/小红花应急行动.html`。全部资源内嵌，不需要服务器或网络。导出校验摘要在同目录 `导出校验.json`。重复导出会更新这个 HTML；发布前先备份上个版本。

## 2. 玩家操作与判定表

| 物件 → 区域 | 实际状态变化与演出 | 时长 |
| --- | --- | --- |
| 点击燃气开关 | 旋钮原位转动 90°，炉火熄灭，油火仍待盖严 | 800 ms |
| 锅盖 → 油锅 | 锅盖平稳覆盖整个锅口，火焰收缩；锅盖始终绘制在锅上方 | 1000 ms |
| 人物 → 门外安全区 | 关火和盖盖都完成后，人物向门内移动、缩小，恢复平静 | 1200 ms |
| 水杯 → 油锅 | 杯子倾倒、水滴飞溅、火焰蹿高、烟增浓、人物惊慌后退 | 1050 ms |
| 小湿抹布 → 油锅 | 本关小化纤抹布着火、火势加剧，提示不适合覆盖 | 1050 ms |
| 厨房适用灭火器 → 错误区/空白 | 喷射偏移，提示对准火焰根部 | 950 ms |
| 厨房适用灭火器 → 锅口根部 | 暂时压低火势；不代替关火、盖盖两项训练 | 950 ms |
| 餐盘、菜刀 → 油锅/其他区 | 轻晃弹回；不直接修改风险、火势、错误次数 | 450 ms |

先关火或先盖锅盖都可通关，推荐先关火。动作完成前不计入目标，进行中拒绝第二次操作。已成功使用的锅盖/开关不允许重复操作。已盖住的油锅不会因拖入水杯而凭空重新燃烧。

燃气开关用点击操作；锅盖、人物和工具架物品使用鼠标/触摸拖拽。也支持选物品后点击目标，以及展开底部“键盘操作 / 安全说明”后使用键盘完成。Escape、pointercancel 会取消拖动。坐标由画布实际 DOM 边界换算，不按页面宽高猜位置；人物透明边缘使用同一 PNG 的 alpha 判定。

## 3. 人物和风险

四张同人物、同服装的插画：`worried / panicked / focused / relieved`。紧张是初始状态；风险 ≥70 或错误操作引发惊慌；单项正确动作完成后短暂专注；两项处置均完成后安心。惊慌时身体后退 22 设计像素。左上角同时放大真实人物头像和状态文字，不只靠颜色传达。

风险初始 22，约每 0.85 秒增加 1，范围 0～100。水和小抹布错误每次 +15，叠加火势增量并缓慢衰减。风险满格只提示一次，绝不锁死关卡。错误原因的提示优先，不会被满格通用提示覆盖。任一单项正确动作完成后风险 -12；两项完成后持续降低。页面隐藏暂停计时，每次 delta 最大 100ms，防止返回页面后跳涨。

三项完成后保留 1800ms 的安全场景，再显示结算。无危险操作得 3 花；纠错完成得 2 花。存档按 levelId 保留历史最好结果，不累计刷花。记录不可写时仍能玩。

## 4. 模块边界（AI 修改时必须遵守）

| 文件 | 单一责任 | 不应放入 |
| --- | --- | --- |
| `app/game/kitchen/config.ts` | 素材清单、布局、落点、文案、时长 | DOM、计时器、副作用 |
| `app/game/kitchen/model.ts` | 纯状态机、规则、风险、奖励、表情推导 | Canvas、图片加载、React |
| `app/game/kitchen/animation.ts` | 插值、动作轨迹、人物最终位置 | 修改规则状态、发奖励 |
| `app/game/kitchen/interaction.ts` | 坐标换算、目标区域和初选 | 绘画、风险变化 |
| `components/game/kitchen/asset-loader.ts` | 本地图片加载和 alpha 读取、失败重试 | 目标完成条件 |
| `components/game/kitchen/renderer.ts` | 图层绘制、火焰/烟/喷射、alpha 命中 | 推进规则、保存记录 |
| `components/game/kitchen/scene-canvas.tsx` | Canvas 生命周期、缩放、绘制循环 | 通关规则 |
| `components/game/kitchen/kitchen-player.tsx` | 输入分发、HUD、音效、结算、存档回调 | 重绘人物或器具美术 |
| `app/kitchen.css` | UI 外观与移动适配 | 拼装锅、火焰或人物图画 |

事件契约：`start / reset / hint / tick(ms) / drop(item,zone,at,from)`。`at/from` 均是画布逻辑坐标。纯状态 `Run` 不保存 DOM 或图片实例。

背景绘制为 720×960，画布只显示 720×850，裁掉下方无关空地板；所有互动区域仍完整显示。资源路径必须保留为 `/levels/kitchen-v1/*.png` 字面量，离线导出会自动收集并内嵌。

注意：根目录 `app/game/levels.ts` 仍有旧通用播放器的兼容说明。实际厨房规则以 `app/game/kitchen/` 为准，不能只改旧 actions 就声称新关卡已改变。将来扩成批量处置关时，应先提取经过多关验证的通用规则，不应假装本模块已经是任意 JSON 的解释器。

## 5. 美术生产记录与禁区

本次使用内置 imagegen，无 API Key，不指定或声称已核实某个模型版本。采用风格库的 illustration-art-style 和 character-design-sheet 思路：锁定暖色纸纹、细深线、青绿柜体、同人物服装和四种表情。

- 最终游戏资源：`public/levels/kitchen-v1/`（背景 + 13 个透明 PNG）。
- 选用的生成原图：`outputs/kitchen-review/sources/`；不打进游戏。
- 精确提示词：`docs/kitchen-art-prompts/`。
- 可复现去背、切分、对齐：`scripts/prepare-kitchen-art.py`（需要 Python + Pillow + NumPy + SciPy）。
- 透明验收：`node scripts/check-kitchen-art.mjs`；报告 `outputs/kitchen-review/alpha-validation.json`。
- 深绿底接触表：`outputs/kitchen-review/alpha-contact-sheet.png`；这是素材检查图，不冒充浏览器截图。

生成器给出了 RGB 棋盘格，并未得到真正 alpha。已按用户允许的本地处理流程去背。不能把“看起来像透明”当验收；必须检查 alpha 和全边缘。银色刀面不能被灰白背景阈值误删；玻璃杯内部棋盘格难以可靠去除，改用生成的不透明浅蓝陶瓷水杯，并移除杯把负空间。

不能机械九等分图集：原图锅柄跨格，会被截断。固定裁切框写在处理脚本中；再次生成尺寸不符时脚本会停止，必须重新量取框。人物用共同 470×600 画布对齐头部/脚底，不把每个人的紧包围盒强行拉成相同宽度。

禁止重引入：整块安全图覆盖、重复背景物件、矩形假透明、锅盖在锅后、人物最终站在灶台或物件上、根据图片大小隐式决定目标区。

## 6. 验收清单

自动化：厨房 26 项 + 台风回归 28 项，涵盖燃气仅点击操作、两顺序、动画提交时机、撤离条件、全部错误/无关类型、风险上限、重置、手机坐标、透明点击、锅盖遮挡顺序。另有独立 13 物件透明通道检查。类型检查和主游戏生产构建已通过。

人工浏览器：在主游戏本地开发页面、390×844 尺寸实际拖拽检查。覆盖水杯、抹布、灭火器错误区、无关餐盘、两种安全动作顺序、人物撤离、奖励和刷新存档。检查了初始 / 蹿火 / 盖盖 / 人物撤离 / 结算画面。详情只按实际验收记录更新，不可把纯 reducer 测试写成真机验收。

尚不声称完成：实体 iOS/Android 设备测试、最终单文件 file:// 浏览器运行（内置浏览器安全策略此前已阻止，不绕过）、完整商业发布合规与专业消防审稿。离线导出会做 JavaScript 语法、外部依赖、图片内嵌和哈希校验。

## 7. 科普边界

用户希望小湿抹布触发错误。参考[应急管理部《初期火灾如何救？》](https://www.mem.gov.cn/kp/shaq/201712/t20171213_365921.shtml)与[罗湖区政府《油锅起火该如何处理？》](https://www.szlh.gov.cn/zmhd/wdzsk/content/post_12283035.html)：合适的湿棉布完整覆盖也有适用场景。因此本关明确限定为“小块化纤抹布，无法盖严锅口”，不能宣称所有湿布都易燃或不能覆盖。前述来源只用于核对禁止泼水、关闭热源、盖严锅口和湿布材质边界；不将网页其他建议直接编码进训练。

“先完成关火、盖盖才能获得撤离目标”是小游戏任务条件，不是现实逃生限制。界面、错误提示、结算均提示：现实火势失控立即撤离并拨打 119；儿童不要尝试灭火。正式面向公众商用前，应交由专业消防人员审核。
