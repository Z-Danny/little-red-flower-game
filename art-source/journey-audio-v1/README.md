# 首页与地图配乐：忙归忙，能搞定

用户选中第二轮小样的第 3 首。素材来自 OriginGame Generate MCP 的 `music_v2`，未重新生成。原始 MP3 已保存为 `source.mp3`，不依赖被忽略的 `outputs/` 目录；原提示词、来源与 SHA-256 见 `provenance.json`。

## 制作结果

- 交付文件：`public/audio/journey-v1/busy-rescue-loop.mp3`，192 kbps，48 kHz，双声道，669,357 字节。
- 配置：`content/journey-audio.json`；循环范围是解码后的 `0–27.826083333333333` 秒。
- 数值响度：**-18.00 LUFS、-6.38 dBTP**。这是素材自身的测量值；播放配置的 `gain: 0.65` 会再降低约 3.74 dB。
- `fadeSeconds: 0.25` 用于开始/停止播放的短过渡，不应在每轮循环时重新触发。

## 循环处理

对实际音频的正向对数频谱通量做自相关，最强候选为约 **137.93 BPM**（相关系数 0.600），与约 138 BPM 的脉冲相符。依据这个实际周期采用 64 拍（按 4/4 为 16 小节），没有只依赖生成提示词。

从源音频 0.024 秒开始保留 27.826083333333333 秒，保留原时间轴约 92.68%。源结尾带有衰减及接近静音的尾部，循环时去掉这段以维持推进感。首 40 ms 使用切点结束之后的连续音频，按余弦形等增益曲线交叉到对应的原开头，两个权重之和始终为 1。循环周期保持 64 拍，整首没有加入周期性淡入、淡出或静音。

这能够支持数值连续性和节拍周期判断，**不能证明和声、旋律和人耳听感无缝**；小节相位也未经过人耳确认。

## 编码与检查

MP3 写入 Xing/LAME 无缝编码信息。ffmpeg 解码得到 **1,335,652 帧**，与编辑后的 PCM 完全一致。MP3 容器时长含编码帧边界，运行时应以解码时长和配置循环点为准。浏览器可能按设备采样率重采样，由集成测试另行确认。

最终解码波形左右声道的循环边界步幅约 0.01225 / 0.00623，低于边界附近普通单采样步幅的 99 分位 0.03997 / 0.05309；数值仅用于排除明显突变，不构成试听验收。

- 解码、非有限值、目标响度、峰值余量、无缝解码帧数：passed。
- 人耳试听、音乐循环接缝听感、浏览器播放、真机、游戏混音：**not_run**（本素材制作步骤没有扬声器播放；集成步骤的验证另行记录）。
- 完整测量：`verification.json`。

## 复现

需要 Python 3、NumPy、ffmpeg（包含 libmp3lame）和 ffprobe。从项目根目录运行：

```sh
python3 art-source/journey-audio-v1/build_loop.py
```

脚本对选中源文件解码、检测节奏、编辑循环、以固定增益调整响度、编码并复测。只使用 NumPy 和 ffmpeg，不会播放声音。复现会更新交付 MP3、配置和测量报告；不同编码器版本可能导致 SHA-256 或末位测量值变化。
